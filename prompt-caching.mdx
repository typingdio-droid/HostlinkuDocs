Prompt caching dapat mengurangi biaya pemrosesan prefix yang berulang. Dukungan, ambang token, masa hidup, dan tarif cache mengikuti model serta penyedia. Cache hit tidak dijamin hanya karena prompt dikirim ulang.

## Harga dan penggunaan

Periksa `pricing.cache_read` dan `pricing.cache_write` pada [`GET /v1/models`](/models) dengan API key yang akan dipakai. Harga mengikuti Service Mode key dan dihitung per 1M token; tarif yang tidak tersedia dapat tidak dicantumkan. Cache write dapat lebih mahal daripada input biasa, sehingga penghematan bergantung pada jumlah token dan cache hit berikutnya.

Console **Logs** menampilkan Input, Output, Cache Read, Cache Write, dan biaya final. Rincian Cache Write 5m/1h hanya terisi jika upstream melaporkannya; `-` berarti rincian tidak tersedia, bukan nol. Pada histori lama, sebagian rincian biaya memakai tarif sekarang; total historis tetap tersimpan. Lihat [Billing](/billing).

## Menyusun prompt

Letakkan konten statis lebih dulu: definisi tools, system prompt/dokumen, lalu pesan lama. Pesan pengguna terbaru dan nilai yang berubah diletakkan sesudahnya. Perubahan prefix, termasuk timestamp atau urutan tools, dapat menyebabkan cache miss.

Untuk Claude pada jalur yang mendukungnya, beri `cache_control` pada blok statis. Penanda tidak memaksa cache hit: blok tetap harus memenuhi ketentuan model dan upstream.

## Anthropic Messages

Contoh berikut memakai `cache_control` pada blok `system`:

```bash
curl https://api.hostlinku.com/v1/messages \
  -H "x-api-key: sk-your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "system": [{
      "type": "text",
      "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
      "cache_control": {"type": "ephemeral"}
    }],
    "messages": [{"role": "user", "content": "Ringkas bagian 3."}]
  }'
```

Contoh `usage` saat cache write:

```json
{
  "usage": {
    "input_tokens": 16,
    "cache_creation_input_tokens": 3601,
    "cache_read_input_tokens": 0,
    "output_tokens": 4
  }
}
```

`cache_creation_input_tokens` menghitung cache write; `cache_read_input_tokens` menghitung cache read. Nilai read yang lebih besar dari nol menandakan penggunaan cache yang dilaporkan upstream. Keduanya dapat nol jika request tidak memenuhi syarat cache atau informasi cache tidak tersedia.

## OpenAI Chat Completions

Untuk model Claude, bridge meneruskan `cache_control` dari content part ke blok Anthropic:

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "system", "content": [{
        "type": "text",
        "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
        "cache_control": {"type": "ephemeral"}
      }]},
      {"role": "user", "content": "Ringkas bagian 3."}
    ]
  }'
```

Pada format Chat Completions, `usage.prompt_tokens` sudah termasuk token cache. `usage.prompt_tokens_details.cached_tokens` menghitung cache read dan `cache_write_tokens` menghitung cache write bila tersedia. Jangan menjumlahkan token cache sekali lagi ke `prompt_tokens`.

## Agent dan protokol lain

Aplikasi yang sudah memasang `cache_control` dapat memakainya saat diarahkan ke Hostlinku; perilaku tergantung versi aplikasi dan model. Lihat [Integrasi IDE & Agent](/integrations). Model lain dapat memakai cache otomatis upstream tanpa penanda tersebut, tetapi hit dan pelaporannya berbeda per model.

`/v1/responses` belum menyediakan penanda eksplisit `cache_control` pada bridge Chat Completions. Cache otomatis dan token cache yang dilaporkan native/upstream tetap mengikuti model. Untuk penanda Claude pada contoh di atas, gunakan `/v1/messages` atau `/v1/chat/completions`.

## Memeriksa cache hit

1. Kirim prompt yang memenuhi syarat model, lalu periksa Cache Write/Read di **Logs**.
2. Kirim prefix yang sama dalam masa cache upstream dan periksa apakah Cache Read terisi.
3. Bandingkan request dengan model, Service Mode, dan panjang output yang sama. Selisih biaya juga dipengaruhi token output, bukan hanya cache.

Jika Cache Read tetap nol, periksa prefix, ukuran blok, dukungan model, dan masa hidup cache. Lihat [Bantuan](/support) jika informasi usage tidak sesuai.
