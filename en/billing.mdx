Hostlinku uses prepaid credits. **1 <CreditIcon /> = $1**. The organization’s balance is shared among associated API keys and constitutes service credits. Refunds are subject to the [Refund Policy](/en/legals/refund-policy).

## Add to organization balance

1. Open [Console](https://console.hostlinku.com) → **Billing** → top-up.
2. Select an amount or preset, then a payment method.
3. Select a bank for VA or a coin/network for crypto.
4. Check the total, bonus, exchange rate, and fees, then pay according to the instructions. Credits are automatically added once payment is verified.

| Method | Provider | Page |
|---|---|---|
| QRIS | iPaymu Direct | Hostlinku Pay, Rupiah QR Code |
| Virtual Account | iPaymu Direct | Hostlinku Pay, virtual account (VA) number |
| Crypto | Heleket | Heleket Payment Page |

Minimum, maximum, and available methods follow the payment summary. The default crypto payment invoice is **20 minutes**; providers may extend this. The link validity period differs from the payment deadline: follow the displayed deadline, and reopen the transaction from Billing if the link is no longer valid.

The Pay link can be accessed without logging in for a single transaction. Keep the link private.

## Usage fees

Pricing depends on the model and the **Service Mode key**. Check the [model catalog](/en/models), **Models** in the Console, or `GET /v1/models` with the key you plan to use.

| Dimensions | Price unit |
|---|---|
| Input, output, read/write cache | Per 1M tokens |
| Web search, if available | Per 1K calls |

Token cache is included in the input and is no longer counted as a regular input. Billing uses upstream usage; if usage is unavailable, costs may be estimated.

- **Non-streaming chat**: The cost is displayed at `hostlinku.cost`.
- **SSE Streaming**: Check the final cost in **Logs / Analytics / Billing** after the stream is complete.

## Available balance and key limit

`available = balance − reserved`. A portion of the balance is temporarily reserved for ongoing requests. Once the request is complete, usage charges are calculated and the remaining reservation is released.

"Top-up" adds to the organization’s balance, not the **Monthly Spending Limit** key. If you receive a `402 PAYMENT_REQUIRED` response, check the message: top up the balance if it’s insufficient, or wait for the limit to reset or adjust the limit key if it has been reached. Details in [Authentication](/en/authentication).

<a id="transaksi-dan-invoice"></a>

## Transactions and invoices

Go to **Billing** to view your transaction history and paid top-up invoices. Print or save a PDF via your browser. Invoices from the Pay link require a valid link and a paid transaction.

**Billing Profile** is stored in the browser and affects the invoice output from the Console. The profile has not yet been synchronized to other devices or the invoice server; Pay invoices may display different details.

Monitor your balance in the Console. Auto-recharge settings and low-balance emails are not yet available in the active Billing workflow.

## Historical costs and analytics details

The total cost of billed requests is stored in the log. Some input/output/cache details are recalculated using current rates, so the details may differ from historical totals. Changes to the display of details do not result in the rebilling of old requests.
