Usage is limited by rate limits, key credit limits, and organizational balances.

<a id="kuota-bersama-organisasi"></a>

<a id="shared-organization-quota"></a>

## Organization-wide quota

The following quotas are shared by all API keys and members within the same organization. Adding a key or using another member’s account does not increase the quota.

| Service Mode | Requests per minute | `input` tokens per minute | `output` tokens per minute |
|---|---|---|---|
| Performance | 600 | 6,500,000 | 200,000 |
| Low-Cost | 600 | 6,500,000 | 200,000 |
| Dedicated | 600 | 6,500,000 | 200,000 |

<a id="batas-endpoint-lain"></a>

## Other endpoint limits

The limits for the Console, login, and checkout endpoints are calculated per IP address and are separate from the model usage quota.

| Scope | Limits | Grouping |
|---|---|---|
| Console/public endpoint with a general limiter | **120 requests / 60 seconds** | Per IP |
| Endpoint with authentication limiter | **30 attempts / 15 minutes** | Per IP |
| GET checkout with token | **90 requests / 60 seconds** | Per IP |
| Token-based checkout mutation | **15 requests / 60 seconds** | Per IP |

<Callout type="tip" title="Wait before retrying a request that was rejected with a 429 error">

Check the Reset header or `Retry-After` if available. Reduce concurrency and use exponential backoff with jitter. Repeating requests continuously without a pause will not resolve the limitation.

The limiter endpoint returns `RateLimit-Limit`, `RateLimit-Remaining`, and `RateLimit-Reset` (seconds). When a 429 error occurs, `Retry-After` or `retry-after-ms` may also be returned.
</Callout>

<a id="limit-kredit-api-key"></a>

<a id="api-key-credit-caps"></a>

## API key credit limit

The Console form offers a **Monthly Spending Limit**. The key management API accepts `daily`, `weekly`, `monthly`, or `null` for no reset. The daily window begins at 00:00 UTC, the weekly window on Monday at 00:00 UTC, and the monthly window on the 1st at 00:00 UTC. See [Authentication](/en/authentication).

The limit is based on the recorded cost for the key, not the number of tokens. Once reached, subsequent requests are rejected with a `402 PAYMENT_REQUIRED` response. Additional balance does not change the key limit.

<a id="reservasi-saldo"></a>

<a id="balance-reservations"></a>

## Balance reservation

The gateway reserves an estimated cost from the organization’s balance, forwards requests, and then settles the cost based on upstream usage. The remaining reservation is released. If usage data is unavailable, billing may use the estimate. A failure without billable usage releases the reservation.

The new request balance is `available = balance − reserved`. The balance and key limits must be sufficient; see [Billing & Balance](/en/billing).

<a id="memantau-di-console"></a>

<a id="monitor-in-the-console"></a>

## Monitoring in the Console

| Menu | Data |
|---|---|
| **Overview / Analytics** | Summary of requests, tokens, cache, and costs by time period |
| **Logs** | Model, status, token, cost, latency, TTFT, and request details |
| **API Keys** | Status, Service Mode, expiration, limit, and key usage |
| **Billing** | Organization balance, top-up, transaction, invoice |

Non-streaming chat completion includes `hostlinku.cost`. Streaming SSE does not guarantee cost blocks per chunk; check the final cost via Logs/Analytics/Billing. `x-request-id` helps link requests to logs.

<a id="isi-log-dan-retensi"></a>

## Log content and retention

Body logging is **disabled by default**. If enabled by an admin, the content is size-limited and credential fields are filtered; the default body retention period is 14 days. Usage/transaction metadata is still stored. See [Privacy](/en/legals/privacy-policy).

Raw health probe data is stored for **30 days** by default, then periodically purged. Request content has a separate retention period of **14 days**. Usage and transaction metadata is retained.

<a id="biaya-historis"></a>

## Historical costs

The total billed cost continues to use the value stored in the log. Some analytics details are recalculated based on the current token and rates; these details may differ from historical totals without re-billing.

<a id="arti-429-dan-402"></a>

<a id="understanding-429-and-402"></a>

## Meaning of 429 and 402

| Code | Meaning | Actions |
|---|---|---|
| `429 RATE_LIMITED` | The request limit has been exceeded | Wait for reset, backoff, reduce concurrency |
| `402 PAYMENT_REQUIRED` | Available balance is insufficient or the key limit has been reached | Read the message: top up balance, wait for reset, or change the appropriate limit |
