Usage is constrained by rate limits, key credit caps, and organization balance.

## Shared organization quota

All API keys and members in the same organization share this quota. Adding keys or using another member account does not increase it.

| Service Mode | Requests/minute | Input tokens/minute | Output tokens/minute |
|---|---|---|---|
| Performance | 600 | 6,500,000 | 200,000 |
| Low-Cost | 600 | 6,500,000 | 200,000 |
| Dedicated | 600 | 6,500,000 | 200,000 |

## Other endpoint limits

Console, login, and checkout endpoint limits are counted per IP, separately from model usage quotas.

| Scope | Limit | Grouping |
|---|---|---|
| Console/public endpoints using the general limiter | **120 requests / 60 seconds** | Per IP |
| Endpoints using the authentication limiter | **30 attempts / 15 minutes** | Per IP |
| Token-based checkout GET | **90 requests / 60 seconds** | Per IP |
| Token-based checkout mutations | **15 requests / 60 seconds** | Per IP |

<Callout type="tip" title="Pause before retrying 429">

Read reset headers or `Retry-After` when available. Reduce concurrency and use exponential backoff with jitter. Repeated immediate retries do not resolve the limit.

</Callout>

## API key credit caps

The Console form offers **Monthly Spending Limit**. The key-management API also supports `daily`, `weekly`, `monthly`, and total `lifetime`/no reset. Daily windows begin at 00:00 UTC, weekly at Monday 00:00 UTC, and monthly at 00:00 UTC on the first day. See [Authentication](/en/authentication).

Caps use recorded costs for the key, not token counts. Once reached, subsequent requests return `402 PAYMENT_REQUIRED`. Adding balance does not change a key's cap.

## Balance reservations

The gateway reserves an estimated cost from organization balance, forwards the request, and settles using upstream usage. It releases the unused reservation. If usage is missing, billing may estimate it. Failures with no billable usage release the reservation.

Balance for new requests is `available = balance − reserved`. Both balance and key caps must allow the request; see [Billing & Balance](/en/billing).

## Monitor in the Console

| Menu | Data |
|---|---|
| **Overview / Analytics** | Requests, tokens, cache, and costs by time range |
| **Logs** | Model, status, tokens, cost, latency, TTFT, and request details |
| **API Keys** | Status, Service Mode, expiry, caps, and key usage |
| **Billing** | Organization balance, top-ups, transactions, invoices |

Non-streaming chat completions include `hostlinku.cost`. SSE streaming does not guarantee a cost block in chunks; check the final charge in Logs/Analytics/Billing. `x-request-id` helps connect requests with logs.

## Log content and retention

Body logging is **off by default**. If enabled by an admin, content is size-limited and credential fields are redacted; body retention defaults to 14 days. Usage/transaction metadata remains stored. See [Privacy](/en/legals/privacy-policy).

Raw health probe records have a default retention of **30 days** and are cleaned up periodically. Probe retention is separate from 14-day request body retention; usage and transaction metadata is retained.

## Historical costs

Charged totals use stored log values. Some analytics breakdowns are recalculated from tokens and current rates; they may differ from historical totals without charging old requests again.

## Understanding 429 and 402

| Code | Meaning | Action |
|---|---|---|
| `429 RATE_LIMITED` | Request count limit exceeded | Wait for reset, back off, reduce concurrency |
| `402 PAYMENT_REQUIRED` | Insufficient available balance or key cap reached | Read the message: top up, wait for reset, or adjust the appropriate cap |
