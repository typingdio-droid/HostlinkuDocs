Hostlinku provides endpoints compatible with
[OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)—the format
used by **Codex CLI**, **OpenAI Agents SDK**, and the `client.responses.create()` method in the OpenAI SDK.
Simply replace the base URL; the API key, balance, Service Mode, rate limit, and Request Logs are the same as
`/v1/chat/completions` and `/v1/messages`.

```http
POST https://api.hostlinku.com/v1/responses
Authorization: Bearer sk-your-api-key
Content-Type: application/json
```

A successful response includes `x-request-id`; a non-streaming successful response also includes `x-model` (the model’s public slug).

<Callout type="note" title="Model and tool compatibility">
  `model` uses the public slug from the [model catalog](/en/models). The gateway provides native and bridge paths to Chat Completions depending on the deployment model. In Performance and Low-Cost Service Modes, Codex only supports OpenAI/GPT models; Claude and domestic models are not supported. For Dedicated, tool support depends on the model and deployment. Response format support does not imply that every model supports all Responses features or Codex tools.
</Callout>

Select an available model for the Service Mode API key. Vision, reasoning, caching, JSON schema, and tool calls follow the model’s capabilities. Native responses pass through upstream features; the Chat Completions bridge supports messages, model-supported images, and the `type: "function"` tool. Hosted/custom tools and encrypted reasoning require native support.

## Quick Setup

Complete guides for each tool are available in the [Codex CLI](/en/integrations/codex-cli) and
[OpenAI Agents SDK](/en/integrations/agents-sdk).

**Codex CLI** (`~/.codex/config.toml`)

```toml
model = "gpt-5-5"
model_provider = "hostlinku"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

```bash
export HOSTLINKU_API_KEY=sk-your-api-key
codex
```

**Python (Official OpenAI SDK)**

```python
from openai import OpenAI

client = OpenAI(api_key="sk-your-api-key", base_url="https://api.hostlinku.com/v1")

response = client.responses.create(
    model="gpt-5-5",
    instructions="Jawab singkat dalam bahasa Indonesia.",
    input="Apa itu API gateway?",
    max_output_tokens=256,
)
print(response.output_text)
print(response.usage.input_tokens, response.usage.output_tokens)
```

**Node.js**

```ts
import OpenAI from "openai";

const client = new OpenAI({ apiKey: "sk-your-api-key", baseURL: "https://api.hostlinku.com/v1" });
const response = await client.responses.create({
  model: "claude-sonnet-4-6",
  input: "Halo!",
  max_output_tokens: 256,
});
console.log(response.output_text);
```

**OpenAI Agents SDK (Python)**

```python
from agents import Agent, Runner, set_default_openai_client, set_tracing_disabled
from openai import AsyncOpenAI

set_default_openai_client(AsyncOpenAI(api_key="sk-your-api-key", base_url="https://api.hostlinku.com/v1"))
set_tracing_disabled(True)  # tracing OpenAI tidak tersedia lewat gateway

agent = Agent(name="Asisten", instructions="Jawab singkat.", model="gpt-5-5")
result = Runner.run_sync(agent, "Sebutkan 3 bahasa pemrograman.")
print(result.final_output)
```

<a id="parameter-body"></a>

## Body parameters

| Parameter | Type | Notes |
|---|---|---|
| `model` | `string` | **Required.** Hostlinku model slug. |
| `input` | `string` | `array` | **Required.** Single text or array items: `message` (`role` + `content` containing `input_text`/`input_image`/…), `function_call`, `function_call_output`, `reasoning`. |
| `instructions` | `string` | System prompts (developer messages). |
| `max_output_tokens` | `integer` | Token output limit. A `400` error is returned if the model’s output limit is exceeded. |
| `stream` | `boolean` | `true` for SSE (see below). |
| `tools`, `tool_choice`, `parallel_tool_calls` | - | Function calling format Responses (`{ "type": "function", "name", "parameters" }`). |
| `reasoning` | `object` | E.g., `{ "effort": "low" \| "medium" \| "high", "summary": "auto" }`. |
| `include` | `string[]` | E.g., `["reasoning.encrypted_content"]`; the availability of encrypted items depends on native upstream support for Responses. Bridge chat does not retain encrypted reasoning items. |
| `text`, `truncation`, `temperature`, `top_p`, `metadata`, `user`, `prompt_cache_key`, `safety_identifier` | - | As per OpenAI specifications; passed on to the model. |
| `store` | `boolean` | Always treated as `false` (see *Stateless*). |
| `previous_response_id`, `conversation`, `background` | - | Non-null `previous_response_id` and `conversation` are rejected with a `400 invalid_request_error`; `background: true` is rejected. The field may be omitted; `background: false` is accepted. |

Other fields in the Response body are passed through. Parameters may be passed through, ignored, or rejected depending on the route and upstream support; schema acceptance does not guarantee model features. Invalid bodies are rejected with a `400 invalid_request_error` response, with details provided in `error.details.issues`.

<Callout type="important" title="Stateless - send the full history in `input`">
  Send the full history in `input` with `store: false`. Non-null `previous_response_id` and `conversation`, as well as `background: true`, are rejected. `GET`/`DELETE /v1/responses/{id}` is not available. Reasoning items can be reused on native paths; the bridge chat bypasses them.
</Callout>

## Non-streaming response

```json
{
  "id": "resp_…",
  "object": "response",
  "created_at": 1791850828,
  "completed_at": 1791850829,
  "status": "completed",
  "error": null,
  "incomplete_details": null,
  "model": "gpt-5-5",
  "output": [
    { "id": "rs_…", "type": "reasoning", "summary": [], "encrypted_content": "…" },
    {
      "id": "msg_…",
      "type": "message",
      "status": "completed",
      "role": "assistant",
      "content": [{ "type": "output_text", "text": "API gateway adalah …", "annotations": [] }]
    }
  ],
  "usage": {
    "input_tokens": 20,
    "output_tokens": 19,
    "total_tokens": 39,
    "input_tokens_details": { "cached_tokens": 0 },
    "output_tokens_details": { "reasoning_tokens": 12 }
  },
  "previous_response_id": null,
  "store": false,
  "hostlinku": { "cost": 0.00031, "currency": "🪙", "serviceMode": "performance", "latencyMs": 1420 }
}
```

`id` and `model` are always Hostlinku public identifiers. The `hostlinku` block is an extension (the OpenAI SDK
ignores it) containing the cost <CreditIcon />, Service Mode API key, and latency. `status: "incomplete"` with
`incomplete_details.reason = "max_output_tokens"` means the output was truncated by `max_output_tokens`
- Billing remains based on actual tokens.

<Callout type="warning" title="Model reasoning + small `max_output_tokens`">
  In reasoning models (e.g., DeepSeek V4, GPT-6, Claude with "thinking"), thinking tokens are
  counted toward `max_output_tokens`. Small values (e.g., `16`) are typically exhausted by the `reasoning`
  alone → `status: "incomplete"` and `output` contains only the `reasoning` item without a `message`.
  Use `max_output_tokens` ≥ 256 or lower `reasoning.effort` to `"low"`.
</Callout>

<Callout type="note" title="Usage Conventions for API Responses">
  Just like Chat Completions, `input_tokens` **already contains** cached tokens; details are in
  `input_tokens_details.cached_tokens`. `output_tokens` contains `reasoning_tokens`. Hostlinku billing
  is calculated based on these components at their respective prices (see [Billing](/en/billing)).
</Callout>

## Streaming (`stream: true`)

The gateway streams SSE events using the API response framing (`event:` + `data:`), including
the `sequence_number` from the upstream:

```text
event: response.created
data: {"type":"response.created","sequence_number":0,"response":{"id":"resp_…","object":"response","status":"in_progress","model":"gpt-5-5","output":[],…}}

event: response.in_progress
data: {"type":"response.in_progress","sequence_number":1,"response":{…}}

event: response.output_item.added
data: {"type":"response.output_item.added","sequence_number":2,"output_index":0,"item":{"id":"msg_…","type":"message","status":"in_progress","role":"assistant","content":[]}}

event: response.content_part.added
data: {"type":"response.content_part.added","sequence_number":3,"item_id":"msg_…","output_index":0,"content_index":0,"part":{"type":"output_text","text":"","annotations":[]}}

event: response.output_text.delta
data: {"type":"response.output_text.delta","sequence_number":4,"item_id":"msg_…","output_index":0,"content_index":0,"delta":"API gateway"}

event: response.output_text.done
data: {"type":"response.output_text.done","sequence_number":5,"item_id":"msg_…","output_index":0,"content_index":0,"text":"API gateway adalah …"}

event: response.content_part.done
data: {"type":"response.content_part.done","sequence_number":6,…}

event: response.output_item.done
data: {"type":"response.output_item.done","sequence_number":7,"output_index":0,"item":{"id":"msg_…","type":"message","status":"completed",…}}

event: response.completed
data: {"type":"response.completed","sequence_number":8,"response":{"id":"resp_…","status":"completed","model":"gpt-5-5","output":[…],"usage":{"input_tokens":20,"output_tokens":19,"total_tokens":39,…}}}
```

Note:

- Final usage, if provided by the upstream, is found in `response.completed` or `response.incomplete`. Cost uses this usage; if usage is empty or zero, the gateway may use a reservation estimate. The `hostlinku.cost` extension is available in non-streaming success responses; do not expect it in every SSE event.
- Tool calls are routed through `response.output_item.added` (`type: "function_call"`),
  `response.function_call_arguments.delta`, and `response.function_call_arguments.done`.
- If a stream fails midway, the gateway sends `event: error` with
  `{"type":"error","code":…,"message":…}` and **does not** send a fake `response.completed`.
- Errors occurring before the first byte (out of balance, model not found, rate limit) are returned as
  standard JSON responses with the correct HTTP status—the OpenAI SDK maps these to exceptions
  (`AuthenticationError`, `NotFoundError`, `RateLimitError`, …).

## Tool calling (function calling)

```python
tools = [{
    "type": "function",
    "name": "get_time",
    "description": "Waktu saat ini di sebuah kota",
    "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
}]

r1 = client.responses.create(model="claude-sonnet-4-6", input="Jam berapa sekarang di Jakarta?", tools=tools, store=False)
call = next(o for o in r1.output if o.type == "function_call")

# Giliran berikutnya: kirim ulang riwayat + hasil tool (stateless)
r2 = client.responses.create(
    model="claude-sonnet-4-6",
    tools=tools,
    store=False,
    input=[
        {"type": "message", "role": "user", "content": [{"type": "input_text", "text": "Jam berapa sekarang di Jakarta?"}]},
        *[o.model_dump(exclude_none=True) for o in r1.output],
        {"type": "function_call_output", "call_id": call.call_id, "output": '{"time": "10:00 WIB"}'},
    ],
)
print(r2.output_text)
```

## Error format

```json
{ "error": { "message": "The API key is invalid or has been revoked.", "type": "authentication_error", "param": null, "code": "invalid_api_key" } }
```

| HTTP | `error.type` | `error.code` | Common causes |
|---|---|---|---|
| 400 | `invalid_request_error` | `invalid_request` / `model_not_in_service_mode` | The body is invalid; `max_output_tokens` exceeds the model limit; `previous_response_id` was sent; the model is not available in Service Mode key. |
| 401 | `authentication_error` | `invalid_api_key` | API key is incorrect/revoked/expired, or a request without an API key. |
| 402 | `insufficient_quota` | `insufficient_quota` | Insufficient balance or API key credit limit reached. |
| 403 | `permission_error` | - | Account suspended / access denied. |
| 404 | `not_found_error` | `model_not_found` / `not_found` | There is no model slug; or `GET /v1/responses/{id}` (stateless). |
| 429 | `rate_limit_error` | `rate_limit_exceeded` | The request limit has been reached (see the `Retry-After` header). |
| 503 | `server_error` | `model_unavailable` / `server_error` | Model/upstream is unavailable. Check the catalog for alternative models; retry with a delay if there is a temporary outage. |

The table lists errors handled by the protocol. Restrictions on requests or parsing the body before the handler can use the standard Hostlinku format; see [Error](/en/errors).

Error messages are sanitized to obscure internal identifiers; some reasons for upstream rejection may still appear.
