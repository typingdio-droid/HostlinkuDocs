Hostlinku provides an endpoint compatible with the [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)-the format used by the **Codex CLI**, **OpenAI Agents SDK**, and the `client.responses.create()` method in the OpenAI SDK. Simply replace the base URL; the API key, balance, Service Mode, rate limit, and Request Logs are the same as for `/v1/chat/completions` and `/v1/messages`.

```http
POST https://api.hostlinku.com/v1/responses
Authorization: Bearer sk-your-api-key
Content-Type: application/json
```

Successful responses include `x-request-id`; successful non-streaming responses also include `x-model` (the public model slug).

<Callout type="note" title="Model and tool compatibility">
  `model` uses a public slug from the [model catalog](/en/models). The gateway offers native Responses and a Chat Completions bridge according to the model deployment. Response-format compatibility does not mean every model supports all Responses features or Codex tools.
</Callout>

Choose a model available in the API key Service Mode. Vision, reasoning, caching, JSON schema, and tool calling depend on the model. Native Responses passes upstream features through; the Chat Completions bridge supports messages, model-supported images, and `type: "function"` tools. Hosted/custom tools and encrypted reasoning require native support.

## Quick Setup

Complete guides for each tool are available in the [Codex CLI](/en/integrations/codex-cli) and the [OpenAI Agents SDK](/en/integrations/agents-sdk).

**Codex CLI** (`~/.codex/config.toml`)

```toml
model = "gpt-5-5"
model_provider = "hostlinku"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

```bash
export HOSTLINKU_API_KEY=sk-your-api-key
codex
```

**Python (Official OpenAI SDK)**

```python
from openai import OpenAI

client = OpenAI(api_key="sk-your-api-key", base_url="https://api.hostlinku.com/v1")

response = client.responses.create(
    model="gpt-5-5",
    instructions="Jawab singkat dalam bahasa Indonesia.",
    input="Apa itu API gateway?",
    max_output_tokens=256,
)
print(response.output_text)
print(response.usage.input_tokens, response.usage.output_tokens)
```

**Node.js**

```ts
import OpenAI from "openai";

const client = new OpenAI({ apiKey: "sk-your-api-key", baseURL: "https://api.hostlinku.com/v1" });
const response = await client.responses.create({
  model: "claude-sonnet-4-6",
  input: "Halo!",
  max_output_tokens: 256,
});
console.log(response.output_text);
```

**OpenAI Agents SDK (Python)**

```python
from agents import Agent, Runner, set_default_openai_client, set_tracing_disabled
from openai import AsyncOpenAI

set_default_openai_client(AsyncOpenAI(api_key="sk-your-api-key", base_url="https://api.hostlinku.com/v1"))
set_tracing_disabled(True)  # OpenAI tracing is not available through the gateway

agent = Agent(name="Asisten", instructions="Jawab singkat.", model="gpt-5-5")
result = Runner.run_sync(agent, "Sebutkan 3 bahasa pemrograman.")
print(result.final_output)
```

## Body Parameters

| Parameter | Type | Description |
|---|---|---|
| `model` | `string` | **Required.** Hostlinku model slug. |
| `input` | `string` \| `array` | **Required.** A single text string or an array of items: `message` (`role` + `content` containing `input_text`/`input_image`/…), `function_call`, `function_call_output`, `reasoning`. |
| `instructions` | `string` | System prompt (developer message). |
| `max_output_tokens` | `integer` | Output token limit. Returns a `400` error if the model's output limit is exceeded. |
| `stream` | `boolean` | `true` for SSE (see below). |
| `tools`, `tool_choice`, `parallel_tool_calls` | - | Function calling format Responses (`{ "type": "function", "name", "parameters" }`). |
| `reasoning` | `object` | E.g., `{ "effort": "low" \| "medium" \| "high", "summary": "auto" }`. |
| `include` | `string[]` | E.g., `["reasoning.encrypted_content"]`; encrypted items depend on upstream native Responses support. The chat bridge does not preserve encrypted reasoning items. |
| `text`, `truncation`, `temperature`, `top_p`, `metadata`, `user`, `prompt_cache_key`, `safety_identifier` | - | As specified by OpenAI; passed to the model. |
| `store` | `boolean` | Always treated as `false` (see *Stateless*). |
| `previous_response_id`, `conversation`, `background` | - | Non-null `previous_response_id` and `conversation` return `400 invalid_request_error`; `background: true` is rejected. Omit these fields; `background: false` is accepted. |

Other Responses body fields are passed through. Parameters may be forwarded, ignored, or rejected depending on the protocol path and upstream support; schema acceptance does not guarantee model support. Invalid bodies return `400 invalid_request_error` with details in `error.details.issues`.

<Callout type="important" title="Stateless - send the full history in `input`">
  Send the full history in `input` with `store: false`. Non-null `previous_response_id` and `conversation`, and `background: true`, are rejected. `GET`/`DELETE /v1/responses/{id}` is unavailable. Reasoning items can be reused on native paths; the chat bridge skips them.
</Callout>

## Non-streaming response

```json
{
  "id": "resp_…",
  "object": "response",
  "created_at": 1791850828,
  "completed_at": 1791850829,
  "status": "completed",
  "error": null,
  "incomplete_details": null,
  "model": "gpt-5-5",
  "output": [
    { "id": "rs_…", "type": "reasoning", "summary": [], "encrypted_content": "…" },
    {
      "id": "msg_…",
      "type": "message",
      "status": "completed",
      "role": "assistant",
      "content": [{ "type": "output_text", "text": "An API gateway is …", "annotations": [] }]
    }
  ],
  "usage": {
    "input_tokens": 20,
    "output_tokens": 19,
    "total_tokens": 39,
    "input_tokens_details": { "cached_tokens": 0 },
    "output_tokens_details": { "reasoning_tokens": 12 }
  },
  "previous_response_id": null,
  "store": false,
  "hostlinku": { "cost": 0.00031, "currency": "🪙", "serviceMode": "performance", "latencyMs": 1420 }
}
```

`id` and `model` are always Hostlinku’s public identifiers. The `hostlinku` block is an extension (the OpenAI SDK ignores it) containing the cost <CreditIcon />, Service Mode API key, and latency. `status: "incomplete"` with `incomplete_details.reason = "max_output_tokens"` means the output was truncated by `max_output_tokens`-you’ll still be billed based on the actual number of tokens.

<Callout type="warning" title="Reasoning model + small `max_output_tokens`">
In reasoning models (e.g., DeepSeek V4, GPT-6, Claude with "thinking"), "thinking" tokens are included in the `max_output_tokens` count. A small value (e.g., `16`) is usually exhausted by the `reasoning` items alone → `status: "incomplete"` and `output` contains only the `reasoning` items without a `message`. Use `max_output_tokens` ≥ 256 or set `reasoning.effort` to `"low"`.
</Callout>

<Callout type="note" title="Responses API Usage Conventions">
Just like Chat Completions, `input_tokens` **already contains** cached tokens; the details are in `input_tokens_details.cached_tokens`. `output_tokens` contains `reasoning_tokens`. Your Hostlinku bill is calculated based on these components at their respective prices (see [Billing](/en/billing)).
</Callout>

## Streaming (`stream: true`)

The gateway forwards SSE events using the Responses API framing (`event:` + `data:`), including the `sequence_number` from the upstream:

```text
event: response.created
data: {"type":"response.created","sequence_number":0,"response":{"id":"resp_…","object":"response","status":"in_progress","model":"gpt-5-5","output":[],…}}

event: response.in_progress
data: {"type":"response.in_progress","sequence_number":1,"response":{…}}

event: response.output_item.added
data: {"type":"response.output_item.added","sequence_number":2,"output_index":0,"item":{"id":"msg_…","type":"message","status":"in_progress","role":"assistant","content":[]}}

event: response.content_part.added
data: {"type":"response.content_part.added","sequence_number":3,"item_id":"msg_…","output_index":0,"content_index":0,"part":{"type":"output_text","text":"","annotations":[]}}

event: response.output_text.delta
data: {"type":"response.output_text.delta","sequence_number":4,"item_id":"msg_…","output_index":0,"content_index":0,"delta":"API gateway"}

event: response.output_text.done
data: {"type":"response.output_text.done","sequence_number":5,"item_id":"msg_…","output_index":0,"content_index":0,"text":"An API gateway is …"}

event: response.content_part.done
data: {"type":"response.content_part.done","sequence_number":6,…}

event: response.output_item.done
data: {"type":"response.output_item.done","sequence_number":7,"output_index":0,"item":{"id":"msg_…","type":"message","status":"completed",…}}

event: response.completed
data: {"type":"response.completed","sequence_number":8,"response":{"id":"resp_…","status":"completed","model":"gpt-5-5","output":[…],"usage":{"input_tokens":20,"output_tokens":19,"total_tokens":39,…}}}
```

Note:

- Final usage is in the `response` object at `response.completed` or `response.incomplete`. Costs use upstream usage; if usage is empty or zero, the gateway may use the reservation estimate. Read final costs in Logs / Analytics / Billing; `hostlinku.cost` is not guaranteed on every SSE chunk.
- The tool call is passed via `response.output_item.added` (`type: "function_call"`),
`response.function_call_arguments.delta`, and `response.function_call_arguments.done`.
- If the stream fails midway, the gateway sends an `event: error` with
`{"type":"error","code":…,"message":…}` and **do not** send a fake `response.completed`.
- Errors occurring before the first byte (insufficient balance, model not found, rate limit) are returned as
A standard JSON response with the correct HTTP status code - the OpenAI SDK maps it to an exception (`AuthenticationError`, `NotFoundError`, `RateLimitError`, …).

## Tool calling (function calling)

```python
tools = [{
    "type": "function",
    "name": "get_time",
    "description": "Waktu saat ini di sebuah kota",
    "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
}]

r1 = client.responses.create(model="claude-sonnet-4-6", input="Jam berapa sekarang di Jakarta?", tools=tools, store=False)
call = next(o for o in r1.output if o.type == "function_call")

# Giliran berikutnya: kirim ulang riwayat + hasil tool (stateless)
r2 = client.responses.create(
    model="claude-sonnet-4-6",
    tools=tools,
    store=False,
    input=[
        {"type": "message", "role": "user", "content": [{"type": "input_text", "text": "Jam berapa sekarang di Jakarta?"}]},
        *[o.model_dump(exclude_none=True) for o in r1.output],
        {"type": "function_call_output", "call_id": call.call_id, "output": '{"time": "10:00 WIB"}'},
    ],
)
print(r2.output_text)
```

## Format error

```json
{ "error": { "message": "The API key is invalid or has been revoked.", "type": "authentication_error", "param": null, "code": "invalid_api_key" } }
```

| HTTP | `error.type` | `error.code` | Common causes |
|---|---|---|---|
| 400 | `invalid_request_error` | `invalid_request` / `model_not_in_service_mode` | Invalid body, `max_output_tokens` exceeds the model limit, `previous_response_id` was sent, model not available in Service Mode key. |
| 401 | `authentication_error` | `invalid_api_key` | Invalid, revoked, or expired API key, or request made without an API key. |
| 402 | `insufficient_quota` | `insufficient_quota` | Insufficient balance or API key credit limit reached. |
| 403 | `permission_error` | - | Account suspended / access denied. |
| 404 | `not_found_error` | `model_not_found` / `not_found` | The model slug does not exist; or `GET /v1/responses/{id}` (stateless). |
| 429 | `rate_limit_error` | `rate_limit_exceeded` | The request limit has been reached (see the `Retry-After` header). |
| 503 | `server_error` | `model_unavailable` / `server_error` | Model/upstream unavailable. Check the catalog and replacements; retry with a delay for temporary outages. |

The table shows protocol-handled errors. Request rate limiting or body parsing before the handler can use the general Hostlinku format; see [Errors](/en/errors).

Errors are sanitized to mask internal identities; some upstream rejection reasons can still appear.
