The Hostlinku Gateway uses an API key in the format `sk-…` for the endpoint `/v1/*`:

```http
Authorization: Bearer sk-your-api-key
Content-Type: application/json
```

The header `x-api-key: sk-…` is also accepted. Create and manage keys in [Console](https://console.hostlinku.com) → **API Keys**.

<Callout type="important" title="API key and Console session">

The API key is used for `/v1/chat/completions`, `/v1/messages`, `/v1/responses`, and `/v1/models`. Protected account endpoints at `/api/*` use the Console login session and reject API key authentication with a `403 API_KEY_NOT_ALLOWED` error. The login cookie does not replace the API key for `/v1/*`.

</Callout>

## Log in to the Console

[Sign in](https://api.hostlinku.com/api/auth2/login) or [sign up](https://api.hostlinku.com/api/auth2/register) to access the Keycloak login page, then return to the Console.

Console uses the server session `hl_sid`; `hl_session` is a JWT cookie for some workflows. The browser manages it automatically. Passkey, TOTP, and recovery codes are available in **Settings → Security**.

## Create and manage API keys

1. Go to **API Keys → Create API Key**.
2. Enter a name (maximum 64 characters) and select **Service Mode**: **Performance**, **Low-Cost**, or **Dedicated**. The default setting is Performance. The mode determines the catalog, routing, and pricing that apply to that key.
3. Select an expiration period: **30 days** (default), **60 days**, **90 days**, or **Never**.
4. If necessary, enable **Monthly Spending Limit** and enter the monthly credit limit.
5. Copy the one-time secret that appears and store it in a server environment variable.

There is currently no endpoint scope option on the API key form. Keys remain restricted to Service Mode, balance, expiration, credit limit, and rate limit. The correct list of models for your key can be obtained from [`GET /v1/models`](/en/models).

Secrets are stored as SHA-256 hashes, so they cannot be reproduced. Console supports editing, enabling/disabling, and deleting keys. If a secret is lost or leaked, create a replacement, verify the request, and then disable the old key.

<a id="limit-kredit-per-api-key"></a>

## Credit limit per API key

Console offers a **Monthly Spending Limit**. The key management API supports the following periods (UTC calendar):

| Period | Cost window based on the UTC calendar |
|---|---|
| `daily` | As of 00:00 UTC on the current day |
| `weekly` | Starting Monday at 00:00 UTC this week |
| `monthly` | Effective from the 1st at 00:00 UTC of the current month |
| `null` / without reset | Total during the key’s active period |

Costs are accumulated based on recorded request usage for each key. Once the limit is reached, subsequent requests are rejected with a `402 PAYMENT_REQUIRED` response. The limit per key is separate from the organization’s credit balance: a top-up increases the balance but does not raise the key limit. See [Billing & Balance](/en/billing).

## Rate limit and error

Quotas are shared by all API keys and organization members **for each Service Mode**. Adding keys or member accounts does not increase the quota. Limit values and how to handle 429 errors are in [Usage & Limits](/en/usage-and-limits).

| Conditions | HTTP | Code |
|---|---|---|
| Key does not exist, is invalid, is inactive, or has expired | 401 | `UNAUTHORIZED` |
| The API key is used for authentication at the Console account endpoint | 403 | `API_KEY_NOT_ALLOWED` |
| Available balance is low or the key credit limit has been reached | 402 | `PAYMENT_REQUIRED` |
| Rate limit exceeded | 429 | `RATE_LIMITED` |

<Callout type="tip" title="Store the key on the server">

Use `HOSTLINKU_API_KEY` in the server environment. Create a separate key for each application or environment, set appropriate expiration dates and limits, and do not store secrets in a browser or public repository.

</Callout>
