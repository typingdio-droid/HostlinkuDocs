The Hostlinku gateway uses `sk-…` API keys for `/v1/*` endpoints:

```http
Authorization: Bearer sk-your-api-key
Content-Type: application/json
```

The `x-api-key: sk-…` header is also accepted. Create and manage keys in the [Console](https://console.hostlinku.com) → **API Keys**.

<Callout type="important" title="API keys and Console sessions">

Use an API key for `/v1/chat/completions`, `/v1/messages`, `/v1/responses`, and `/v1/models`. Protected account endpoints under `/api/*` use a Console login session and reject API key authentication with `403 API_KEY_NOT_ALLOWED`. Login cookies do not replace API keys on `/v1/*`.

</Callout>

## Console login

[Sign in](https://api.hostlinku.com/api/auth2/login) or [sign up](https://api.hostlinku.com/api/auth2/register) to open Keycloak login and return to the Console.

The Console uses the `hl_sid` server session; `hl_session` is a JWT cookie for some flows. Your browser manages them automatically. Passkeys, TOTP, and recovery codes are available in **Settings → Security**.

## Create and manage an API key

1. Open **API Keys → Create API key**.
2. Enter a name (up to 64 characters) and choose a **Service Mode**: **Performance**, **Low-Cost**, or **Dedicated**. The form defaults to Performance. The mode determines the key's catalog, routing, and prices.
3. Select **30 days** (default), **60 days**, **90 days**, or **Never**.
4. Optionally enable **Monthly Spending Limit** and enter a monthly credit cap.
5. Copy the secret shown once and store it in a server environment variable.

The current API key form has no endpoint scope selector. Service Mode, balance, expiry, credit limit, and rate limit still constrain the key. Obtain the correct model list for your key from [`GET /v1/models`](/en/models).

The server stores a SHA-256 hash of the secret, so it cannot display the secret again. The Console supports editing, disabling/enabling, and deleting keys. If a secret is lost or exposed, create a replacement, verify a request, and disable the old key.

## Credit limit per API key

The Console offers **Monthly Spending Limit**. The key-management API supports these UTC-calendar periods:

| Period | Cost window in the UTC calendar |
|---|---|
| `daily` | Since 00:00 UTC today |
| `weekly` | Since Monday 00:00 UTC this week |
| `monthly` | Since 00:00 UTC on the first day of this month |
| `lifetime` / no reset | Total during the key's active lifetime |

Usage is accumulated from recorded request costs for the key. Once the cap is reached, subsequent requests return `402 PAYMENT_REQUIRED`. A key's cap differs from the organization's credit balance: topping up adds balance but does not increase the key's cap. See [Billing & Balance](/en/billing).

## Rate limits and errors

The service quota is **600 requests, 6,500,000 input tokens, and 200,000 output tokens per minute**, shared within the same organization. All organization API keys and members are affected when the quota is reached. See [Usage & Limits](/en/usage-and-limits) for quota details and handling 429.

| Condition | HTTP | Code |
|---|---|---|
| Missing, invalid, disabled, or expired key | 401 | `UNAUTHORIZED` |
| API key used to authenticate a Console account endpoint | 403 | `API_KEY_NOT_ALLOWED` |
| Insufficient available balance or key credit cap reached | 402 | `PAYMENT_REQUIRED` |
| Rate limit exceeded | 429 | `RATE_LIMITED` |

<Callout type="tip" title="Keep keys on the server">

Use `HOSTLINKU_API_KEY` in your server environment. Create separate keys for each application or environment, set suitable expiry and limits, and keep secrets out of browsers and public repositories.

</Callout>
