Prompt caching can reduce the cost of processing repeated prefixes. Support, token thresholds, lifetime, and cache prices depend on the model and provider. Resending a prompt does not guarantee a cache hit.

## Pricing and usage

Check `pricing.cache_read` and `pricing.cache_write` in [`GET /v1/models`](/en/models) using the intended API key. Prices follow the key's Service Mode and are per 1M tokens; unavailable rates may be omitted. Cache writes can cost more than ordinary input, so savings depend on token counts and subsequent hits.

Console **Logs** shows Input, Output, Cache Read, Cache Write, and final cost. Cache Write 5m/1h details are populated only when upstream reports them; `-` means unavailable detail, not zero. Some historical cost breakdowns use current rates while the historical total remains stored. See [Billing](/en/billing).

## Arrange the prompt

Put static content first: tool definitions, system prompt/documents, then older messages. Place the latest user message and changing values afterwards. Prefix changes, including timestamps or tool order, can cause cache misses.

For Claude on supported routes, add `cache_control` to the static block. The marker does not force a hit: the block must still meet model and upstream requirements.

## Anthropic Messages

This example places `cache_control` on the `system` block:

```bash
curl https://api.hostlinku.com/v1/messages \
  -H "x-api-key: sk-your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "system": [{
      "type": "text",
      "text": "<long, unchanged instructions and reference documents>",
      "cache_control": {"type": "ephemeral"}
    }],
    "messages": [{"role": "user", "content": "Summarize section 3."}]
  }'
```

Example `usage` during a cache write:

```json
{
  "usage": {
    "input_tokens": 16,
    "cache_creation_input_tokens": 3601,
    "cache_read_input_tokens": 0,
    "output_tokens": 4
  }
}
```

`cache_creation_input_tokens` counts cache writes; `cache_read_input_tokens` counts cache reads. A read value greater than zero indicates upstream-reported cache usage. Both can be zero if a request is ineligible for caching or cache information is unavailable.

## OpenAI Chat Completions

For Claude models, the bridge forwards `cache_control` from a content part to an Anthropic block:

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "system", "content": [{
        "type": "text",
        "text": "<long, unchanged instructions and reference documents>",
        "cache_control": {"type": "ephemeral"}
      }]},
      {"role": "user", "content": "Summarize section 3."}
    ]
  }'
```

In Chat Completions, `usage.prompt_tokens` already includes cache tokens. `usage.prompt_tokens_details.cached_tokens` counts cache reads and `cache_write_tokens` counts cache writes when available. Do not add cache tokens to `prompt_tokens` again.

## Agents and other protocols

Apps that already set `cache_control` can use it when pointed at Hostlinku; behavior depends on app version and model. See [IDE & Agent Integrations](/en/integrations). Other models may use automatic upstream caching without that marker, but hits and reporting vary by model.

`/v1/responses` does not currently provide an explicit `cache_control` marker through the Chat Completions bridge. Automatic caching and tokens reported by native/upstream routes remain model-dependent. For the Claude markers shown above, use `/v1/messages` or `/v1/chat/completions`.

## Check cache hits

1. Send a prompt that meets the model's requirements, then inspect Cache Write/Read in **Logs**.
2. Resend the same prefix within the upstream cache lifetime and check for Cache Read.
3. Compare requests with the same model, Service Mode, and output length. Output tokens also affect the cost difference.

If Cache Read stays zero, check the prefix, block size, model support, and cache lifetime. See [Support](/en/support) if the usage information is unexpected.
