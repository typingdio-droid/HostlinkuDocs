Prompt caching can reduce the processing cost of repetitive prefixes. Support, token thresholds, lifetime, and cache rates depend on the model and provider. A cache hit is not guaranteed simply because a prompt is resubmitted.

<a id="harga-dan-penggunaan"></a>

## Pricing and usage

Check `pricing.cache_read` and `pricing.cache_write` on [`GET /v1/models`](/en/models) using the API key you plan to use. Pricing follows the Service Mode key and is calculated per 1M tokens; rates that are not available may be omitted. Cache writes may be more expensive than regular requests, so cost savings depend on the number of tokens and subsequent cache hits.

Console **Logs** display Input, Output, Cache Read, Cache Write, and the final cost. Cache Write details for 5m/1h are only populated if the upstream reports them; `-` means the details are unavailable, not zero. In older history records, some cost details use current rates; historical totals are still retained. See [Billing](/en/billing).

## Compose the prompt

Place static content first: tool definitions, system prompts/documentation, then older messages. Place the most recent user messages and values that have changed afterward. Changes to prefixes, including timestamps or tool order, can cause cache misses.

For Claude on supported channels, include `cache_control` in static blocks. The marker does not force a cache hit: the block must still comply with the model and upstream requirements.

## Anthropic Messages

The following example uses `cache_control` in the `system` block:

```bash
curl https://api.hostlinku.com/v1/messages \
  -H "x-api-key: sk-your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "system": [{
      "type": "text",
      "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
      "cache_control": {"type": "ephemeral"}
    }],
    "messages": [{"role": "user", "content": "Ringkas bagian 3."}]
  }'
```

Example of `usage` during a cache write:

```json
{
  "usage": {
    "input_tokens": 16,
    "cache_creation_input_tokens": 3601,
    "cache_read_input_tokens": 0,
    "output_tokens": 4
  }
}
```

`cache_creation_input_tokens` counts cache writes; `cache_read_input_tokens` counts cache reads. A read value greater than zero indicates cache usage reported by the upstream. Both can be zero if the request does not meet cache criteria or cache information is unavailable.

## OpenAI Chat Completions

For the Claude model, the bridge passes `cache_control` from the content part to the Anthropic block:

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "system", "content": [{
        "type": "text",
        "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
        "cache_control": {"type": "ephemeral"}
      }]},
      {"role": "user", "content": "Ringkas bagian 3."}
    ]
  }'
```

In the Chat Completions format, `usage.prompt_tokens` already includes cache tokens. `usage.prompt_tokens_details.cached_tokens` counts read cache tokens, and `cache_write_tokens` counts write cache tokens when available. Do not add cache tokens to `prompt_tokens` again.

## Agent and other protocols

Applications that have already implemented `cache_control` can use it when redirected to Hostlinku; behavior depends on the application version and model. See [IDE & Agent Integration](/integrations). Other models can use automatic upstream caching without that marker, but hits and reporting vary by model.

`/v1/responses` does not yet provide an explicit `cache_control` header in the Chat Completions bridge. Automatic caching and cache tokens reported by native/upstream systems still follow the model. For the Claude header in the example above, use `/v1/messages` or `/v1/chat/completions`.

## Checking cache hits

1. Submit a prompt that meets the model’s requirements, then check the Write/Read Cache in **Logs**.
2. Send the same prefix within the upstream cache period and check if the Cache Read field is populated.
3. Compare "request" with "model," "Service Mode," and the same output length. Cost differences are also influenced by the output token, not just the cache.

If Cache Read remains at zero, check the prefix, block size, model support, and cache lifetime. See [Help](/en/support) if usage information is incorrect.
