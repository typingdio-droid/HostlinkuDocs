[Codex CLI](https://developers.openai.com/codex/cli) uses the OpenAI Responses protocol. Route custom providers to [`POST /v1/responses`](/en/responses); tool matching and reasoning depend on the model and the Responses route used.

<Steps>

<a id="instal-codex-cli"></a>

<a id="install-codex-cli"></a>

### Install the Codex CLI

```bash
npm install -g @openai/codex
# atau: brew install codex
```

<a id="tambahkan-provider-hostlinku"></a>

<a id="add-hostlinku-as-a-provider"></a>

### Add the Hostlinku provider

Edit `~/.codex/config.toml` (create it if it doesn’t exist). Providers **must** be defined in this
user’s file—`.codex/config.toml` within the project must not override `model_providers` for
security reasons.

```toml
model = "gpt-5-3-codex"
model_provider = "hostlinku"
model_reasoning_effort = "medium"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

<a id="set-api-key-dan-jalankan"></a>

<a id="set-the-api-key-and-run-it"></a>

### Set the API key and run

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # simpan di ~/.zshrc / ~/.bashrc
codex
```

Codex reads the key from the variable named `env_key`; the key is never written to
`config.toml`.

<Callout type="tip" title="Want to manage it via the GUI with a single click?">
  Use the [CC Switch](/en/integrations/cc-switch) desktop app to add and switch
  Codex providers/models without manually editing `config.toml`.
</Callout>

<a id="verifikasi"></a>

### Verification

Send a single simple instruction (e.g., *"explain the structure of this repo"*). The request will appear in
the console → **Request Log** using the `gpt-5-3-codex` model. If you want to verify the endpoint before
opening Codex:

```bash
curl https://api.hostlinku.com/v1/responses \
  -H "Authorization: Bearer $HOSTLINKU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "gpt-5-3-codex", "input": "Halo" }'
```

</Steps>

## Multiple models via profiles

`cepat` and `kuat` are example names you can choose freely; they are not default profiles from Codex or Hostlinku. Profile names may contain letters, numbers, hyphens, and underscores.

Codex reads `~/.codex/config.toml`. When you run `--profile <nama>`, Codex also reads `~/.codex/<nama>.config.toml`. Create a separate file for each profile, with settings at the top level; do not use the `[profiles.*]` section. See the [official Codex profile guide](https://developers.openai.com/codex/config-advanced/#profiles).

The `~/.codex/cepat.config.toml` file:

```toml
model = "gpt-5-6-luna"
model_provider = "hostlinku"
model_reasoning_effort = "low"
```

The `~/.codex/kuat.config.toml` file:

```toml
model = "gpt-6-astra"
model_provider = "hostlinku"
```

The `hostlinku` provider is defined in `~/.codex/config.toml`. Select a profile when running Codex:

```bash
codex --profile kuat
codex --profile cepat "tulis unit test untuk utils/date.ts"
```

<Callout type="warning" title="Model and tool compatibility">
  Use native Responses models supported by your Codex tool version. Bridge Chat Completions supports text and function calls; custom shell/patch tools and encrypted reasoning require native support. If you see `The requested tool type is not supported by this model`, switch models or use the appropriate Chat/Anthropic client. See the [Responses API](/en/responses).
</Callout>

<Callout type="note" title="Stateless">
  Send the full history in `input` and use `store: false`. Hostlinku rejects non-null `previous_response_id` or `conversation` and `background: true`. Encrypted reasoning items can only be used if the upstream path supports them; see [Responses API](/en/responses).
</Callout>

<Callout type="tip" title="Do you just want to replace the default OpenAI endpoint?">
  Alternative without a new provider: set `openai_base_url = "https://api.hostlinku.com/v1"` in
  `config.toml` and `OPENAI_API_KEY=sk-…` (Hostlinku API key). A custom provider is still recommended
  because their names are clearly displayed in the UI and their keys are separate from the original OpenAI keys.
</Callout>

## Troubleshooting

- **`401`** - the variable in `env_key` has not been exported in the shell where `codex` is running.
- **Shell/patch tool did not run** — check tool support in the model and Responses path; a text-only response does not prove the tool was executed.
- **`400 previous_response_id`** — remove `previous_response_id`/`conversation`, resend the full history in `input`, and use `store: false`.
- **Model not found / `404`** - incorrect slug; `/v1/models` displays a valid list for
  your key.
- **Legacy client versions** — update the Codex and use `wire_api = "responses"` as per the [official configuration reference](https://developers.openai.com/codex/config-reference/).
