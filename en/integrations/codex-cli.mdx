[Codex CLI](https://developers.openai.com/codex/cli) uses OpenAI Responses. Point a custom provider at [`POST /v1/responses`](/en/responses); tool and reasoning compatibility depends on the model and Responses path.

<Steps>

### Install Codex CLI

```bash
npm install -g @openai/codex
# or: brew install codex
```

### Add Hostlinku as a provider

Edit `~/.codex/config.toml` (create it if it doesn't exist). Providers **must** be defined in this user file-the `.codex/config.toml` file within the project must not override `model_providers` for security reasons.

```toml
model = "gpt-5-3-codex"
model_provider = "hostlinku"
model_reasoning_effort = "medium"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

### Set the API key and run it

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # simpan di ~/.zshrc / ~/.bashrc
codex
```

Codex reads the key from the variable specified in `env_key`; the key is never written to `config.toml`.

<Callout type="tip" title="Prefer a one-click GUI?">
  Use the [CC Switch](/en/integrations/cc-switch) desktop app to add and switch Codex providers or
  models visually without editing `config.toml` by hand.
</Callout>

### Verification

Send a simple instruction (e.g., *"explain the structure of this repo"*). The request will appear in the console → **Request Log** using the `gpt-5-3-codex` model. If you want to verify the endpoint before opening Codex:

```bash
curl https://api.hostlinku.com/v1/responses \
  -H "Authorization: Bearer $HOSTLINKU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "gpt-5-3-codex", "input": "Halo" }'
```

</Steps>

## Some models via their profiles

Use `[profiles.*]` to switch models/providers without editing the configuration:

```toml
[profiles.cepat]
model = "gpt-5-6-luna"
model_provider = "hostlinku"
model_reasoning_effort = "low"

[profiles.kuat]
model = "gpt-6-astra"
model_provider = "hostlinku"
```

```bash
codex --profile kuat
codex --profile cepat "write unit tests for utils/date.ts"
```

<Callout type="warning" title="Model and tool compatibility">
  Use a native Responses model supporting your Codex version’s tools. The Chat Completions bridge supports text and function calling; custom shell/patch tools and encrypted reasoning require native support. If you receive `The requested tool type is not supported by this model`, change models or use an appropriate Chat/Anthropic client. See [Responses API](/en/responses).
</Callout>

<Callout type="note" title="Stateless">
  Send the full history in `input` and use `store: false`. Hostlinku rejects non-null `previous_response_id` or `conversation` and `background: true`. Encrypted reasoning items require upstream support; see [Responses API](/en/responses).
</Callout>

<Callout type="tip" title="Just want to change the default OpenAI endpoint?">
Alternative without a new provider: set `openai_base_url = "https://api.hostlinku.com/v1"` in `config.toml` and `OPENAI_API_KEY=sk-…` (your Hostlink API key). A custom provider is still recommended because its name is clearly displayed in the UI and its key is separate from the original OpenAI key.
</Callout>

## Troubleshooting

- **`401`** - The variable in `env_key` has not been exported in the shell where `codex` is running.
- **Shell/patch tools do not run** — check the model and Responses path for tool support; a text answer does not prove a tool ran.
- **`400 previous_response_id`** — remove `previous_response_id`/`conversation`, resend the full history in `input`, and use `store: false`.
- **Model not found / `404`** - incorrect slug; `/v1/models` displays a valid list for
Your key.
- **Old client versions** — update Codex and use `wire_api = "responses"` as described in the [official configuration reference](https://developers.openai.com/codex/config-reference/).
