[GitHub Copilot](https://docs.github.com/en/copilot) supports **BYOK (Bring Your Own Key)** on
several surfaces. Where it accepts a custom *base URL*, you can point it to
Hostlinku and use a plan from the catalog with your Hostlinku balance.

| Copilot Interface | Can I be redirected to Hostlinku? | Guidelines |
|---|---|---|
| **Copilot CLI** (`copilot`) | Yes—the environment variable `COPILOT_PROVIDER_*` | [below](#copilot-cli) |
| **GitHub Copilot app** (desktop) | Yes - *Settings → Model providers* (public preview) | [below](#github-copilot-app) |
| **Copilot Chat in VS Code** | Yes - *Custom Endpoint* provider | [VS Code](/en/integrations/vscode) |
| Copilot in JetBrains, Visual Studio, Xcode; inline autocomplete | No—there is no base URL setting | [Limitations](#batasan) |

## Copilot CLI

When the BYOK variable is set, the Copilot CLI sends all model requests to your provider. **Logging in
to GitHub is optional** for this mode.

<Steps>

<a id="set-an-environment-variable"></a>

### Set environment variable

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # API key Hostlinku
export COPILOT_PROVIDER_BASE_URL=https://api.hostlinku.com/v1
export COPILOT_PROVIDER_API_KEY="$HOSTLINKU_API_KEY"
export COPILOT_MODEL=claude-sonnet-4-6
```

`COPILOT_PROVIDER_TYPE` defaults to `openai` (Chat Completions), so it does not need to be set. Copilot
adds `/chat/completions` on its own—the base URL only needs to go up to `/v1`.

<a id="disarankan-beri-tahu-batas-token-model"></a>

<a id="recommended-specify-the-model-token-limit"></a>

### (Recommended) Specify the token model limits

Copilot CLI does not recognize the "Hostlinku" slug, so populate the limit from [catalog](/en/models) so that
the context is properly truncated:

```bash
export COPILOT_PROVIDER_MAX_PROMPT_TOKENS=1000000
export COPILOT_PROVIDER_MAX_OUTPUT_TOKENS=64000
```

Check whether the key has already been set in the same shell before running `copilot`, without printing its value:

```bash
test -n "$COPILOT_PROVIDER_API_KEY" && echo "API key tersedia" || echo "API key belum diatur"
```

<a id="jalankan"></a>

### Run

```bash
copilot
# atau ganti model per sesi
copilot --model gpt-5-5
```

The first request appears in the console → **Request Log**.

</Steps>

<a id="varian-format-anthropic"></a>

### Variant: Anthropic format

For the Claude model via the Messages API (full prompt caching), use the `anthropic` provider with a base
URL **without** `/v1`:

```bash
export COPILOT_PROVIDER_TYPE=anthropic
export COPILOT_PROVIDER_BASE_URL=https://api.hostlinku.com
export COPILOT_PROVIDER_API_KEY="$HOSTLINKU_API_KEY"
export COPILOT_MODEL=claude-sonnet-4-6
```

<Callout type="note" title="The model must support tool calling and streaming">
  Copilot CLI requires *tool calling* and *streaming*, and recommends a minimum context size of 128K tokens. Check all three in the [catalog](/en/models) before selecting a model.
</Callout>

- **Use the API format appropriate for the tool and model.** Chat Completions uses the default provider `openai`; Response limits are described in the [Responses reference](/en/responses).
- **Without a GitHub login**, features that rely on the GitHub server (`/delegate`, GitHub MCP server,
  code search) are unavailable. Log in with `copilot login` if you need those features—the request model
  remains with Hostlinku.
- **`COPILOT_OFFLINE=true`** disables all connections to GitHub (including telemetry). Prompts are still
  sent to `api.hostlinku.com`.

## GitHub Copilot app

The GitHub Copilot desktop app supports custom model providers (public preview). You still
need to log in to GitHub, but **you don’t need the Copilot plan** if you’re only using a custom provider.

<Steps>

<a id="tambah-provider"></a>

<a id="add-a-provider"></a>

### Add provider

Go to app settings → **Model providers** → **Add provider** → select **OpenAI-compatible**.

<a id="isi-detail-provider"></a>

### Provider details

| Field | Value |
|---|---|
| **Display name** | `Hostlinku` |
| **Base URL** | `https://api.hostlinku.com/v1` |
| **API key** | `sk-…` (Hostlinku API key) |

Click **Add provider**. The key is stored in the operating system’s credential store.

<a id="pilih-model-per-sesi"></a>

<a id="select-a-model-per-session"></a>

### Select a per-session model

The Hostlinku model appears in the model picker next to the GitHub model. Select one when starting
an agent session.

</Steps>

For the Claude model, you can also select the **Anthropic** provider and enter the base URL
`https://api.hostlinku.com` (without `/v1`) — available if the provider form displays a base URL field.

<a id="batasan"></a>

## Limitations

- **Copilot in JetBrains, Visual Studio, and Xcode** does not have per-user base URL or custom provider
  settings. In JetBrains, use [JetBrains AI Assistant](/en/integrations/jetbrains)
  or [Junie CLI](/en/integrations/junie) for the Hostlinku model.
- **Inline autocomplete (ghost text)** in all editors always uses the Copilot infrastructure. BYOK
  applies only to chat and agents.
- **Copilot Business/Enterprise:** Organization admins must enable BYOK (and Copilot CLI for
  the Copilot app) in the Copilot policy settings.

## Troubleshooting

| Symptoms | Solution |
|---|---|
| `401` | `COPILOT_PROVIDER_API_KEY` is empty or incorrect in the shell running `copilot`. Use the checks above to ensure the key is filled in; copy it again from the console if it is still rejected. |
| `404` in all requests | The `openai` provider without `/v1`, or the `anthropic` provider with `/v1`. |
| `404 model_not_found` | `COPILOT_MODEL` must be the exact slug from `GET /v1/models`. |
| The error model does not support tool calling | Switch to the *tool calling* model from the [catalog](/en/models). |
| Still using the GitHub model | Variables are exported to other shells—run `copilot` from the same shell or add it to `~/.zshrc`. |
