[Zed](https://zed.dev/docs/ai/use-api-access) supports custom **OpenAI-compatible** providers
via `settings.json`. Models must be explicitly declared (Zed does not perform discovery), and then
the API key must be entered once via the Agent Panel or an environment variable.

<Steps>

<a id="deklarasikan-provider-dan-model"></a>

<a id="declare-the-provider-and-model"></a>

### Declare providers and models

Open `zed: open settings` (⌘/Ctrl + ,) and add:

```json
{
  "language_models": {
    "openai_compatible": {
      "hostlinku": {
        "api_url": "https://api.hostlinku.com/v1",
        "available_models": [
          {
            "name": "claude-sonnet-4-6",
            "display_name": "Claude Sonnet 4.6 (Hostlinku)",
            "max_tokens": 1000000,
            "capabilities": { "tools": true, "images": true, "parallel_tool_calls": true }
          },
          {
            "name": "gpt-5-5",
            "display_name": "GPT-5.5 (Hostlinku)",
            "max_tokens": 1000000,
            "capabilities": { "tools": true, "images": true, "parallel_tool_calls": true }
          },
          {
            "name": "deepseek-v4-flash",
            "display_name": "DeepSeek V4 Flash (Hostlinku)",
            "max_tokens": 1000000,
            "capabilities": { "tools": true, "images": false }
          }
        ]
      }
    }
  },
  "agent": {
    "default_model": { "provider": "hostlinku", "model": "claude-sonnet-4-6" }
  }
}
```

`api_url` must end with `/v1` without a trailing slash. `max_tokens` is the context size
of the model (see `context_window` in the [catalog](/en/models)); `name` must be the exact slug.

<a id="masukkan-api-key"></a>

### Enter the API key

Choose one of the following:

- **Agent Panel** → settings icon (`agent: open settings`) → search for provider **hostlinku** → paste
  API key `sk-…`. Zed stores it in the system keychain, not in `settings.json`.
- **Environment variables** with the provider ID in uppercase + `_API_KEY`:

```bash
export HOSTLINKU_API_KEY=sk-your-api-key
```

Run Zed from a shell that has already exported those variables (or add them to your shell profile
and then log in again).

<a id="pilih-model-di-agent-panel"></a>

### Select a model in the Agent Panel

Open the Agent Panel (⌘/Ctrl + ?) → model selector → **hostlinku** group. Send a message and check
the request in the console → **Request Log**.

</Steps>

<a id="opsi-model-lanjutan"></a>

## Advanced model options

| Field | When to use |
|---|---|
| `reasoning_effort` (`"low"`/`"medium"`/`"high"`) | Model reasoning (GPT-5.x, Claude 4.6, DeepSeek V4). |
| `capabilities.max_tokens_parameter: true` | Only if the model rejects `max_completion_tokens`; Hostlinku accepts both, so leave it at the default. |
| `capabilities.chat_completions: false` | Switch the model to the Responses API (`/v1/responses`)—also supported by Hostlinku, but the default Chat Completions are more thoroughly tested in Zed. |

<Callout type="note" title="Edit Predictions are not included">
  The *edit predictions* (inline autocomplete) feature in Zed is configured separately in `edit_predictions`
  and uses the `/v1/completions` (FIM) endpoint, which is not provided by Hostlinku. Use Hostlinku
  for the Agent Panel, inline assistant, and threads; leave *edit predictions* on the default provider.
</Callout>

## Troubleshooting

- **Provider not found** - `settings.json` is invalid (comma/parentheses). Check `zed: open log`.
- **`401`** - The key has not been entered for the `hostlinku` provider, or the env var was exported after Zed
  was started; restart Zed.
- **Tool calls are ignored**—ensure `capabilities.tools: true` is set for that model.
- **Full context is too fast** - `max_tokens` is too small compared to the model’s `context_window`;
  adjust according to the catalog.
