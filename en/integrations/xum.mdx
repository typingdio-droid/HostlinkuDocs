[Xum](https://xum.cdr.dev/config/providers) (formerly **Mux**) runs multiple coding agents
in parallel, each with an isolated workspace, from a desktop or browser. Xum supports
**custom providers** with your choice of API format—the cleanest way to add Hostlinku without
changing the built-in OpenAI/Anthropic provider.

<Steps>

<a id="simpan-api-key-di-file"></a>

<a id="save-the-api-key-to-a-file"></a>

### Store the API key in a file

```bash
mkdir -p ~/.config/hostlinku
printf '%s' 'sk-your-api-key' > ~/.config/hostlinku/api-key
chmod 600 ~/.config/hostlinku/api-key
```

<a id="tambahkan-provider-hostlinku"></a>

<a id="add-hostlinku-as-a-provider"></a>

### Add the Hostlinku provider

Edit `~/.xum/providers.jsonc` and add a new provider:

```jsonc
{
  // Semua model katalog lewat Chat Completions
  "hostlinku": {
    "providerType": "openai-compatible",
    "displayName": "Hostlinku",
    "baseUrl": "https://api.hostlinku.com/v1",
    "apiKeyFile": "~/.config/hostlinku/api-key",
    "models": ["claude-sonnet-4-6", "gpt-5-5", "deepseek-v4-flash"],
  },
  // Opsional: model Claude lewat Anthropic Messages (prompt caching penuh)
  "hostlinku-claude": {
    "providerType": "anthropic-messages",
    "displayName": "Hostlinku (Anthropic)",
    "baseUrl": "https://api.hostlinku.com",
    "apiKeyFile": "~/.config/hostlinku/api-key",
    "models": ["claude-sonnet-4-6", "claude-haiku-4-5"],
  },
}
```

For `anthropic-messages`, Xum adds `/v1` on its own, so the base URL is written **without** `/v1`.
Provider IDs (`hostlinku`, `hostlinku-claude`) must be lowercase and must not match the names of
built-in providers.

<a id="pilih-model"></a>

### Select a model

Open the model picker (or `/model`) and select a model from the **Hostlinku** group. `models` is only a list of
suggestions—other slugs from the [catalog](/en/models) can still be typed directly. Requests appear in the
console → **Request Log**.

</Steps>

<a id="alternatif-provider-openai-bawaan"></a>

<a id="alternative-the-built-in-openai-provider"></a>

## Alternative: built-in OpenAI provider

If you prefer to use only one provider, configure the default **OpenAI** provider to use Hostlinku via the
Chat Completions wire format (**Settings → Providers → OpenAI**, or in `providers.jsonc`):

```jsonc
{
  "openai": {
    "apiKey": "sk-your-api-key",
    "baseUrl": "https://api.hostlinku.com/v1",
    "wireFormat": "chatCompletions",
  },
}
```

<Callout type="note" title="Why &quot;chatCompletions&quot;?">
  OpenAI’s default wire format is the Responses API, while Responses on Hostlinku are
  *stateless* ([details](/en/responses)). Chat Completions accepts all catalog models—including
  Claude—without that restriction.
</Callout>

## Troubleshooting

| Symptoms | Solution |
|---|---|
| `401` | The contents of the `apiKeyFile` are incorrect (contain newlines or spaces) or the key has been revoked. |
| `404` | `anthropic-messages` with a double `/v1`—write the base URL as `https://api.hostlinku.com`. |
| "Provider" does not appear | Provider IDs use uppercase letters and periods, or conflict with built-in provider names. |
| `404 model_not_found` | The "slug" is a typo—copy it from `GET /v1/models`. |
