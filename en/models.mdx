Hostlinku provides a single centralized model catalog. Each model has a unique **slug** used
in the `model` parameter in [Chat Completions](/en/chat-completions), complete with context size,
capabilities, and price per token.

## `GET /v1/models`

Returns all models with the status `available`, that are not deprecated, and are available for the
**Service Mode API key** being used (Performance, Low-Cost, or Dedicated), along with the price <CreditIcon /> per 1M tokens
in that mode.

```http
GET https://api.hostlinku.com/v1/models
Authorization: Bearer sk-your-api-key
```

Example:

```bash
curl https://api.hostlinku.com/v1/models \
  -H "Authorization: Bearer sk-your-api-key"
```

Response (example truncated; the exact values for your account are retrieved from this endpoint):

```json
{
  "object": "list",
  "service_mode": "performance",
  "data": [
    {
      "id": "claude-haiku-4-5",
      "object": "model",
      "created": 1791380432,
      "owned_by": "hostlinku",
      "context_window": 200000,
      "capabilities": [
        "text",
        "tool-calling",
        "function-calling",
        "structured-outputs",
        "json-mode",
        "streaming",
        "code-generation",
        "long-context",
        "multilingual"
      ],
      "service_mode": "performance",
      "pricing": {
        "input": 0.84,
        "output": 4.2,
        "cache_read": 0.084,
        "cache_write": 1.05,
        "unit": "1M_tokens",
        "currency": "🪙"
      },
      "health": "operational"
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `service_mode` (list & item levels) | The Service Mode API keys used are: `performance`, `low_cost`, or `dedicated`. The list of models varies by mode. |
| `id` | Model slug, the value used in the `model` field in `/v1/chat/completions`, `/v1/messages`, and `/v1/responses`. |
| `created` | The time the model was added to the catalog (Unix epoch, seconds). |
| `owned_by` | Always use `"hostlinku"`—an indicator that the model is managed by the Hostlinku catalog. |
| `context_window` | Maximum context size in tokens (input + output). |
| `capabilities` | List of capabilities, e.g., `vision`, `tool-calling`, `json-mode`, `reasoning`, `long-context`. |
| `pricing` | The pricing object for that Service Mode; `null` if the model does not yet have a price in that mode. `pricing.unit` is always `"1M_tokens"`, and `pricing.currency` contains the credit symbol (1 <CreditIcon /> = $1). |
| `pricing.input` / `pricing.output` | Price per **1M tokens** (not per 1 token or per 1K) for prompt tokens and response tokens. |
| `pricing.cache_read` / `pricing.cache_write` | Price per 1M tokens for 5-minute cache read/cache write. Rates that are not available may be omitted; see [Prompt Caching](/en/prompt-caching). |

<Callout type="note" title="&quot;Pricing&quot; refers to customer pricing">
`pricing` is the customer price for the Service Mode key, including margin. In non-streaming responses, the cost is available at `hostlinku.cost`; usage and costs can also be viewed in the Console logs.
</Callout>

## Public catalog (no authentication required)

Without an API key, use the following endpoints to compare models and Service Modes:

```http
GET https://api.hostlinku.com/api/public/models-v2
GET https://api.hostlinku.com/api/public/service-modes
```

`models-v2` returns `{status, currency, models}`. Each model contains `slug`, `displayName`, `contextTokens`, `maxOutputTokens` (if available), `capabilities`, `serviceModes`, and the price per mode in `modes`. `service-modes` returns `{status, data}`, which contains a summary of the modes and their corresponding models.

To view the list and prices applicable to a specific API key, use `GET /v1/models`.

## How to choose a model

1. **Specify requirements**: general chat, reasoning (_reasoning_), vision/multimodal, tool calling,
   or structured JSON output. Check the `capabilities` field.
2. **Note the context size**: make sure `context_window` is large enough for your prompt and output.
3. **Compare prices**: `pricing.input` for prompt tokens and `pricing.output` for
   response tokens; reasoning models are generally more expensive in terms of output.
4. **Start with smaller models**: for development, lightweight models (e.g., `gpt-6-luna`,
   `deepseek-v4-1-flash`, `qwen3-6-plus`) are significantly cheaper; upgrade to a higher-tier model only if
   the quality is insufficient.
5. **See the console**: the **Model** menu at [console.hostlinku.com](https://console.hostlinku.com)
   displays a catalog with the same pricing and capabilities, plus a detail page for each model.

<Callout type="tip" title="Model ID">
Copy the slug exactly from `GET /v1/models` into the `model` field. An unknown slug may result in `MODEL_NOT_FOUND`; a model not available at the key may result in `MODEL_NOT_IN_SERVICE_MODE` or `MODEL_UNAVAILABLE`.
</Callout>

<a id="routing-dan-failover"></a>

## Routing and failover

The gateway selects a service path based on the model and the Service Mode key. Retry or failover depends on available paths and the type of failure; not all models have a backup path. The model ID in the request remains the same.
