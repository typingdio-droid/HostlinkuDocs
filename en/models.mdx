Hostlinku provides a single centralized model catalog. Each model has a unique **slug** that is used in the `model` parameter in [Chat Completions](/en/chat-completions), along with context size, capabilities, and price per token.

## `GET /v1/models`

Returns all models that are marked as `available`, not yet deprecated, and available for the **Service Mode API key** being used (Performance, Low-Cost, or Dedicated), along with the price <CreditIcon /> per 1M tokens in that mode.

```http
GET https://api.hostlinku.com/v1/models
Authorization: Bearer sk-your-api-key
```

Example:

```bash
curl https://api.hostlinku.com/v1/models \
  -H "Authorization: Bearer sk-your-api-key"
```

Response (example truncated; the exact value for your account is retrieved from this endpoint):

```json
{
  "object": "list",
  "service_mode": "performance",
  "data": [
    {
      "id": "claude-haiku-4-5",
      "object": "model",
      "created": 1791380432,
      "owned_by": "hostlinku",
      "context_window": 200000,
      "capabilities": [
        "text",
        "tool-calling",
        "function-calling",
        "structured-outputs",
        "json-mode",
        "streaming",
        "code-generation",
        "long-context",
        "multilingual"
      ],
      "service_mode": "performance",
      "pricing": {
        "input": 0.84,
        "output": 4.2,
        "cache_read": 0.084,
        "cache_write": 1.05,
        "unit": "1M_tokens",
        "currency": "🪙"
      },
      "health": "operational"
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `service_mode` (level list & item) | Service Mode API key used: `performance`, `low_cost`, or `dedicated`. The list of models varies by mode. |
| `id` | Model slug; the value used in the `model` field in `/v1/chat/completions`, `/v1/messages`, and `/v1/responses`. |
| `created` | The time the model was added to the catalog (Unix epoch, seconds). |
| `owned_by` | Always `"hostlinku"` - indicates that the model is managed by the Hostlinku catalog. |
| `context_window` | Maximum context size in tokens (input + output). |
| `capabilities` | List of capabilities, e.g., `vision`, `tool-calling`, `json-mode`, `reasoning`, `long-context`. |
| `pricing` | The pricing object for that Service Mode; `null` if the model does not yet have a price for that mode. `pricing.unit` is always `"1M_tokens"`, and `pricing.currency` contains the credit symbol (1 <CreditIcon /> = \$1). |
| `pricing.input` / `pricing.output` | Price per **1M tokens** (not per token or per 1K) for prompt tokens / response tokens. |
| `pricing.cache_read` / `pricing.cache_write` | Price per 1M tokens for cache reads / 5-minute cache writes. Unavailable rates may be omitted; see [Prompt Caching](/en/prompt-caching). |

<Callout type="note" title="Pricing is the customer price">
`pricing` is the customer price for the key’s Service Mode, including margin. Non-streaming responses include cost in `hostlinku.cost`; usage and cost are also available in Console logs.
</Callout>

## Public catalog (no authentication required)

Without an API key, use these endpoints to compare models and Service Modes:

```http
GET https://api.hostlinku.com/api/public/models-v2
GET https://api.hostlinku.com/api/public/service-modes
```

`models-v2` returns `{status, currency, models}`. Each model includes `slug`, `displayName`, `contextTokens`, `maxOutputTokens` when available, `capabilities`, `serviceModes`, and mode prices in `modes`. `service-modes` returns `{status, data}` with mode summaries and their models.

For models and prices available to a specific API key, use `GET /v1/models`.

## How to Choose a Model

1. **Determine your needs**: general chat, reasoning, vision/multimodal, tool invocation,
or structured JSON output. Check the `capabilities` field.
2. **Pay attention to the context size**: make sure `context_window` is large enough to accommodate your prompt and output.
3. **Compare prices**: `pricing.input` for prompt tokens and `pricing.output` for tokens
Answer: Reasoning models generally have higher output costs.
4. **Start with a small model**: for development, use a lightweight model (e.g., `gpt-6-luna`,
`deepseek-v4-1-flash`, `qwen3-6-plus`) are much cheaper; only upgrade the model if the quality is insufficient.
5. **View the console**: the **Model** menu at [console.hostlinku.com](https://console.hostlinku.com)
displays a catalog with the same prices and features, plus a detail page for each model.

<Callout type="tip" title="Model ID">
Copy the exact slug from `GET /v1/models` into the `model` field. An unknown slug may return `MODEL_NOT_FOUND`; a model unavailable to the key may return `MODEL_NOT_IN_SERVICE_MODE` or `MODEL_UNAVAILABLE`.
</Callout>

## Routing and Failover

The gateway selects service routes for the model and the key’s Service Mode. Retries or failover depend on available routes and the failure type; not every model has a backup route. Keep the same model ID in your request.
