Gateway endpoints use an API key. Console account endpoints under `/api/*` use a login session. Parameter, vision, reasoning, caching, and tool support depend on the model and protocol route.

| Endpoint | Purpose | Guide |
|---|---|---|
| `GET /v1/models` | Catalog for the key’s Service Mode | [Models](/en/models) |
| `POST /v1/chat/completions` | Chat and SSE streaming | [Chat Completions](/en/chat-completions) |
| `POST /v1/messages` | Anthropic-format messages | [Anthropic Messages](/en/anthropic-messages) |
| `POST /v1/messages/count_tokens` | Unbilled Anthropic-format token counting | [Count tokens](/en/anthropic-messages) |
| `POST /v1/responses` | Stateless Responses | [Responses API](/en/responses) |

## Base URL and authentication

The OpenAI SDK uses `https://api.hostlinku.com/v1`; the Anthropic SDK uses `https://api.hostlinku.com`. The gateway accepts `Authorization: Bearer sk-your-api-key` or `x-api-key`. See [Authentication](/en/authentication).

## Model and tool compatibility

Use catalog slugs on supported endpoints. Format compatibility does not guarantee every client feature. Check [Responses limits](/en/responses) and [your integration](/en/integrations).

## Shared organization quota

Each Service Mode has **600 requests, 6,500,000 input tokens, and 200,000 output tokens per minute**, shared by all organization members and API keys. Login, Console, and checkout have separate per-IP limits. See [Usage & Limits](/en/usage-and-limits).

## Error Codes

Error formats follow the endpoint; errors before its handler can use the common Hostlinku envelope. See [Errors](/en/errors) for codes and handling, and [Anthropic Messages](/en/anthropic-messages#format-error) or [Responses](/en/responses#format-error) for protocol-specific formats.

## Query Available Models

`GET /v1/models` returns models and rates for the key’s Service Mode. The site catalog uses `GET /api/public/models-v2`. See [Models](/en/models) for capabilities and rate details.

## Costs and streaming

Non-streaming chat responses include `hostlinku.cost` and `hostlinku.latencyMs`. After streaming completes, read costs in Logs / Analytics / Billing; do not expect costs in every chunk. Record `x-request-id` when available. See [Billing & Balance](/en/billing).

## Metrics and example figures

| Metric | Meaning |
|---|---|
| `hostlinku.latencyMs` | Time from gateway request receipt to response completion. |
| TTFT | Time to the first observed streaming token; can be absent for non-streaming. |
| TPS | Output tokens per second after the first token, from qualifying stream samples. |

- **Landing animations** use fixed example figures rather than measurements from an inference request while the animation runs.
- **The 60-bar model detail chart** is generated from average/P95 latency and failure aggregates. Each bar is synthetic, rather than a request or probe in sequence. Console usage charts use aggregated request data.
- **The landing footer badge** uses a fixed status; check [Status](https://status.hostlinku.com) for monitoring results and incidents.
- **Reachable** means an HTTP response below 500, including 401/403/404. It indicates endpoint reachability; login and inference success are checked through their respective functions.

Compare metrics for the same period, Service Mode, and sample population. Animations, capacity specifications, traffic aggregates, and benchmarks have different sources.
