These codes use the Chat Completions format. Messages and Responses use their own error formats; see [Errors](/en/errors) for the full reference.

## 401 UNAUTHORIZED

Check the key value and status in Console → **API Keys**. Gateway endpoints accept `Authorization: Bearer sk-...` or `x-api-key`. Do not retry with a key that is invalid, disabled, or expired.

## 402 PAYMENT_REQUIRED

Read the error message: top up the organization balance if available credit is insufficient, or adjust the key credit limit/wait for its reset if the limit is reached. Topping up does not raise a key limit. See [Billing & Balance](/en/billing).

## 404 MODEL_NOT_FOUND

The model slug is not in the catalog. Copy the slug from `GET /v1/models` or the [Models](/en/models) page.

## 400 MODEL_NOT_IN_SERVICE_MODE

The model exists but is not available for the API key's Service Mode. Create a key with the right mode or pick another model.

## 422 VALIDATION_FAILED

Fix the fields listed in `details.issues`, such as empty `messages` or an incorrect field type. Validation uses 422 for Chat Completions and 400 for Messages and Responses. See the [request examples](/en/chat-completions).

## 429 RATE_LIMITED

Each Service Mode quota is shared within the organization. Honor `Retry-After`, use backoff, and reduce bursts. Limiter-rejected requests do not deduct credit. See [Usage & Limits](/en/usage-and-limits).

## 503 MODEL_UNAVAILABLE / UPSTREAM_ERROR

The model is deprecated/unavailable, or the upstream has a temporary issue. Retry later for `UPSTREAM_ERROR`; for `MODEL_UNAVAILABLE`, check for a `replacement_slug`.

<Callout type="note" title="Debugging tip">
  Keep the `x-request-id` response header. It lets support match the request with Console logs.
</Callout>
