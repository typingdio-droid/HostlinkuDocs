## 404 or 503?

| Status | Code | Meaning | Actions |
|---|---|---|---|
| 404 | `MODEL_NOT_FOUND` | "Slug" is not in the catalog | Retrieve the slug from `GET /v1/models` |
| 400 | `MODEL_NOT_IN_SERVICE_MODE` | "Model" exists but is not available for API key mode | Replace "key/mode" or select another model |
| 503 | `MODEL_UNAVAILABLE` | Deprecated/currently unavailable model | Check `replacement_slug` in the error or catalog |
| 503 | `UPSTREAM_ERROR` | Temporary disruption in the upstream | Try again with backoff |

<a id="model-deprecated"></a>

<a id="deprecated-models"></a>

## Deprecated model

Deprecated models no longer appear in `GET /v1/models`. If an error message includes `replacement_slug`, use that slug. The list of active models is available at [Models](/en/models).

<a id="kenapa-model-hilang-dari-key-saya"></a>

<a id="why-did-a-model-disappear-from-my-key"></a>

## Why is the model missing from my key?

The catalog may vary by Service Mode. API keys for Performance and Low-Cost can view different lists of models. Check `GET /v1/models` with the correct key, or create a key with the desired mode in the Console.

<a id="apakah-request-otomatis-dialihkan"></a>

<a id="is-my-request-routed-automatically"></a>

## Are requests automatically redirected?

In the event of an upstream outage, the gateway attempts alternative routes before giving up. However, if the model is not available in the catalog or there are no active routes, the request will still fail. Failover does not change the slug you are using.

<Callout type="tip" title="Quick check">
  Compare the slug with the [model catalog](/en/models), then check the error code details in [Error](/en/errors). If it still fails, send the `x-request-id` to [support](/en/support).
</Callout>
