Penggunaan dibatasi rate limit, limit kredit key, dan saldo organisasi.

## Kuota bersama organisasi

Kuota berikut dipakai bersama oleh semua API key dan anggota dalam organisasi yang sama. Menambah key atau memakai akun anggota lain tidak menambah kuota.

| Service Mode | Request/menit | Token input/menit | Token output/menit |
|---|---|---|---|
| Performance | 600 | 6,500,000 | 200,000 |
| Low-Cost | 600 | 6,500,000 | 200,000 |
| Dedicated | 600 | 6,500,000 | 200,000 |

## Batas endpoint lain

Batas endpoint Console, login, dan checkout dihitung per IP dan terpisah dari kuota penggunaan model.

| Cakupan | Batas | Pengelompokan |
|---|---|---|
| Endpoint Console/publik dengan limiter umum | **120 request / 60 detik** | Per IP |
| Endpoint dengan limiter autentikasi | **30 percobaan / 15 menit** | Per IP |
| GET checkout bertoken | **90 request / 60 detik** | Per IP |
| Mutasi checkout bertoken | **15 request / 60 detik** | Per IP |

<Callout type="tip" title="Tangani 429 dengan jeda">

Baca header reset atau `Retry-After` bila tersedia. Kurangi konkurensi dan gunakan backoff eksponensial dengan jitter. Mengulang request terus-menerus tanpa jeda tidak menyelesaikan pembatasan.

</Callout>

## Limit kredit API key

Form Console menawarkan **Monthly Spending Limit**. API pengelolaan key juga mendukung `daily`, `weekly`, `monthly`, dan total `lifetime`/tanpa reset. Jendela harian dimulai 00:00 UTC, mingguan Senin 00:00 UTC, bulanan tanggal 1 pada 00:00 UTC. Lihat [Autentikasi](/authentication).

Limit memakai biaya yang tercatat untuk key, bukan jumlah token. Setelah tercapai, request berikutnya ditolak `402 PAYMENT_REQUIRED`. Saldo tambahan tidak mengubah limit key.

## Reservasi saldo

Gateway mereservasi estimasi biaya dari saldo organisasi, meneruskan request, lalu menyelesaikan biaya berdasarkan usage upstream. Sisa reservasi dilepas. Bila usage tidak tersedia, billing dapat memakai estimasi. Kegagalan tanpa pemakaian yang dapat ditagih melepaskan reservasi.

Saldo request baru adalah `available = balance − reserved`. Saldo dan limit key perlu mencukupi; lihat [Billing & Saldo](/billing).

## Memantau di Console

| Menu | Data |
|---|---|
| **Overview / Analytics** | Ringkasan request, token, cache, dan biaya menurut rentang waktu |
| **Logs** | Model, status, token, biaya, latensi, TTFT, dan detail request |
| **API Keys** | Status, Service Mode, kedaluwarsa, limit, serta pemakaian key |
| **Billing** | Saldo organisasi, top-up, transaksi, invoice |

Chat completion non-streaming memuat `hostlinku.cost`. Streaming SSE tidak menjamin blok biaya pada chunk; periksa biaya final lewat Logs/Analytics/Billing. `x-request-id` membantu menghubungkan request dengan log.

## Isi log dan retensi

Body logging **nonaktif secara default**. Jika diaktifkan admin, isi dibatasi ukuran dan field kredensial disaring; retensi body default 14 hari. Metadata penggunaan/transaksi tetap disimpan. Lihat [Privasi](/legals/privacy-policy).

Data mentah probe kesehatan memiliki retensi default **30 hari** dan dibersihkan berkala. Retensi probe terpisah dari body request 14 hari; metadata pemakaian dan transaksi tetap disimpan.

## Biaya historis

Total biaya yang ditagihkan tetap memakai nilai tersimpan pada log. Sebagian rincian analytics dihitung ulang dari token dan tarif saat ini; rincian dapat berbeda dari total historis tanpa penagihan ulang.

## Arti 429 dan 402

| Kode | Arti | Tindakan |
|---|---|---|
| `429 RATE_LIMITED` | Batas jumlah request terlampaui | Tunggu reset, backoff, kurangi konkurensi |
| `402 PAYMENT_REQUIRED` | Saldo tersedia kurang atau limit key tercapai | Baca pesan: top-up saldo, tunggu reset, atau ubah limit yang sesuai |
