## 1. Enkripsi dan penyimpanan rahasia

Komunikasi dengan situs, Console, dan API Hostlinku dilindungi oleh **HTTPS (TLS)**. Kredensial dilindungi sesuai jenisnya:

- **Kata sandi akun** tidak disimpan dalam bentuk asli (*plaintext*).
- **API key pelanggan** disimpan sebagai hash **SHA-256** untuk verifikasi, bukan sebagai key yang dapat ditampilkan kembali.
- **Kredensial integrasi**, termasuk kunci upstream provider dan rahasia SSO, dienkripsi menggunakan **AES-256-GCM** pada level aplikasi. Kunci enkripsi berasal dari konfigurasi lingkungan aplikasi, terpisah dari nilai terenkripsi di database.

<a id="autentikasi"></a>

## 2. Autentikasi akun

Layanan identitas Hostlinku tersedia melalui `auth2.hostlinku.com`, dengan protokol federasi identitas standar industri **OpenID Connect (OIDC)** dan **OAuth 2.0**. Alur otorisasi menggunakan **PKCE S256**. Login, verifikasi email, dan pilihan SSO yang diaktifkan dikelola melalui layanan ini.

### Passkey dan Multi-Factor Authentication (MFA)

Selain email dan kata sandi, tersedia metode autentikasi berikut:

- **Passkey (FIDO2/WebAuthn):** autentikasi tanpa kata sandi (*passwordless*) berbasis kriptografi kunci publik. Kunci privat dikelola oleh authenticator atau penyedia passkey dan tidak dikirim ke server saat autentikasi.
- **Authenticator (TOTP):** kode sekali pakai berbasis waktu yang dihasilkan oleh aplikasi authenticator.
- **Kode pemulihan (*recovery codes*):** kode cadangan sekali pakai untuk memulihkan akses saat faktor autentikasi utama tidak tersedia.

Seluruh metode autentikasi dapat dikelola melalui **Console → Settings → Security**. Pilih **Add passkey** untuk mendaftarkan passkey, lalu pilih tombol untuk masuk menggunakan passkey pada halaman login. Simpan kode pemulihan di tempat aman yang tetap dapat diakses saat diperlukan.

### Sesi Console

Console memvalidasi akses melalui sesi yang disimpan di server, dengan cookie **`hl_sid`**. Saat login, backend juga menerbitkan cookie JWT **`hl_session`**. Keduanya dikonfigurasi dengan **`HttpOnly`** dan **`SameSite=Lax`**; **`Secure`** diaktifkan ketika backend berjalan dalam mode produksi.

`HttpOnly` membatasi akses JavaScript halaman ke cookie, `Secure` memastikan cookie hanya dikirim melalui HTTPS, dan `SameSite=Lax` membatasi penyertaan cookie pada request lintas situs.

Akun yang ditangguhkan tidak dapat login maupun memakai API.

<a id="api-key"></a>

## 3. Penanganan API key

- Key ditampilkan utuh sekali saat dibuat dan tidak dapat dilihat ulang.
- Key memiliki Service Mode, masa berlaku, dan batas kredit; dapat dinonaktifkan dari Console. Form saat ini tidak menawarkan scope endpoint.
- Saat body logging aktif, field kredensial disaring sebelum disimpan. Rahasia dalam teks prompt tidak otomatis disaring.
- Identitas upstream provider dan kredensial upstream tidak pernah dikirim ke pelanggan.

<a id="akses"></a>

## 4. Isolasi dan kontrol akses

- Akses request, log, saldo, dan API key diperiksa menurut pengguna, organisasi, dan peran yang berwenang.
- Fungsi admin dibatasi untuk peran admin dan setiap perubahan pengaturan sensitif, termasuk pengaktifan body logging dan penyesuaian saldo, dicatat di audit log.
- Isi request dan respons tidak disimpan secara default; bila body logging diaktifkan, isi dihapus otomatis sesuai masa retensi. Lihat [Kebijakan Privasi](/legals/privacy-policy).

<a id="perlindungan"></a>

## 5. Perlindungan layanan

- Lalu lintas publik melewati Cloudflare untuk mitigasi bot dan serangan volumetrik.
- Kuota penggunaan bersama per organisasi dan batas request per IP dijelaskan di [Pemakaian & Limit](/usage-and-limits).
- Reservasi saldo sebelum request diteruskan mencegah pemakaian melampaui saldo tersedia secara berlebihan.
- Pemantauan kesehatan model dan upstream dipublikasikan di halaman [Status](https://status.hostlinku.com).

<a id="audit"></a>

## 6. Audit log

Kami mencatat peristiwa keamanan seperti login, logout, pendaftaran, pembuatan dan pencabutan API key, serta perubahan pengaturan, beserta waktu, alamat IP, dan user agent. Nilai rahasia tidak pernah ikut tercatat.

<a id="tanggung-jawab"></a>

## 7. Tanggung jawab bersama

<Callout type="note">

Keamanan akun juga bergantung pada kamu:

- gunakan kata sandi yang kuat dan unik;
- simpan API key di sisi server, jangan di kode frontend atau repositori;
- gunakan key terpisah per aplikasi atau lingkungan, beri batas kredit, dan cabut key yang tidak dipakai;
- pantau log dan riwayat transaksi di console untuk mendeteksi pemakaian yang tidak wajar.

</Callout>

<a id="insiden"></a>

## 8. Respons insiden

Saat terjadi insiden keamanan, kami melakukan identifikasi, penahanan, pemulihan, dan evaluasi. Bila insiden menyebabkan kegagalan pelindungan data pribadi, kami memberi tahu pengguna terdampak dan otoritas sesuai ketentuan UU PDP. Bila kami mendeteksi API key yang bocor, key tersebut dapat kami nonaktifkan dan pemiliknya diberi tahu.

<a id="laporan"></a>

## 9. Melaporkan kerentanan

Kirim laporan ke [halo@hostlinku.com](mailto:halo@hostlinku.com) dengan deskripsi, langkah reproduksi, dan dampak yang kamu temukan. Kami akan mengonfirmasi penerimaan dalam 5 hari kerja.

Agar pengujian tetap aman:

- uji hanya dengan akun dan data milik kamu sendiri;
- jangan mengakses, mengubah, atau menghapus data pengguna lain;
- jangan melakukan denial-of-service, spam, atau rekayasa sosial terhadap staf maupun pengguna;
- beri kami waktu yang wajar untuk memperbaiki sebelum mempublikasikan temuan.

Kami tidak akan menempuh tindakan hukum terhadap peneliti yang melapor dengan itikad baik dan mengikuti panduan ini.
