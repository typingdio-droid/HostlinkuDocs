## レスポンス形式

エラー形式はエンドポイントによって異なります。`error.message` は問題の説明です。自動処理にはHTTPステータスとエラーコード／タイプを使ってください。メッセージの言語はサービスによって異なる場合があります。

**Chat Completionsと一般エンドポイント**はHostlinkuコードを使用します：

```json
{
  "status": "error",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The request body is invalid.",
    "details": {
      "issues": [{ "path": "messages", "message": "Array must contain at least 1 element(s)" }]
    }
  }
}
```

**Anthropic Messages**は `error.type` を使用し、`error.code` にHostlinkuコードを含みません：

```json
{"type":"error","error":{"type":"invalid_request_error","message":"The request body is invalid."}}
```

**OpenAI Responses**はOpenAI形式と変換されたコードを使用します：

```json
{"error":{"message":"The request body is invalid.","type":"invalid_request_error","param":null,"code":"invalid_request"}}
```

Responsesの変換例：`UNAUTHORIZED` → `invalid_api_key`、`MODEL_NOT_FOUND` → `model_not_found`、429エラー → `rate_limit_exceeded`。Messagesでは `authentication_error`、`not_found_error`、`rate_limit_error` などのタイプに分類されます。

スキーマ検証エラーはChat Completionsで **422**、Messages/Responsesで **400** です。`error.details` は任意で、`error.details.issues` は不正なフィールドを示します。本文の解析、リクエストのレート制限、未知のパスなど、プロトコルハンドラーより前のエラーには一般のHostlinku形式が使われる場合があります。

## Hostlinkuコード

以下はゲートウェイと一般エンドポイントのHostlinkuコードです。Messages/Responsesでは上記の変換が適用されます。アカウントや決済の各エンドポイントでは、ほかの専用コードが返る場合もあります。

| HTTP | コード | 意味と対処 |
|---|---|---|
| 400 | `BAD_REQUEST` | JSONやパラメータが不正です。モデルの出力上限も確認し、リクエストを修正してください。 |
| 400 | `MODEL_NOT_IN_SERVICE_MODE` | キーのService Modeでモデルを利用できません。同じキーで `GET /v1/models` を確認してください。 |
| 400 | `UPSTREAM_REJECTED` | プロバイダーが拒否しました。サニタイズされた理由を読み、入力を修正してください。 |
| 401 | `UNAUTHORIZED` | 認証がない、無効、取り消し済み、または期限切れです。キーを確認してください。 |
| 402 | `PAYMENT_REQUIRED` | 利用可能残高が不足、またはキーの利用上限に達しました。[Billing](/ja/billing)を確認してください。 |
| 403 | `FORBIDDEN` | アクセスが拒否されました。アカウント権限を確認してください。 |
| 404 | `NOT_FOUND` | パスまたはリソースがありません。URLとIDを確認してください。 |
| 404 | `MODEL_NOT_FOUND` | モデルのslugがありません。カタログを確認してください。 |
| 405 | `METHOD_NOT_ALLOWED` | HTTPメソッドが不正です。`Allow` ヘッダーのメソッドを使用してください。 |
| 413 | `BAD_REQUEST` | 本文が大きすぎます。本文のサイズを減らしてください。 |
| 415 | `BAD_REQUEST` | 本文のエンコーディング／文字セットが未対応です。形式を確認してください。 |
| 422 | `VALIDATION_FAILED` | 本文／クエリの検証に失敗しました。`error.details.issues` のフィールドを修正してください。 |
| 429 | `RATE_LIMITED` | Service Modeごとの組織クォータ、またはエンドポイント／IP上限に達しました。上流からの制限もあります。待機し、同時実行数を減らしてください。 |
| 429 | `MODEL_AT_CAPACITY` | プロバイダー側でモデルが満杯です。再試行の待機時間に従ってください。 |
| 429 | `MODEL_COOLDOWN` | 失敗後にモデルのデプロイが復旧中です。再試行の待機時間に従ってください。 |
| 500 | `INTERNAL` | 内部エラーです。リクエスト情報を保存し、繰り返す場合は報告してください。 |
| 503 | `MODEL_UNAVAILABLE` | モデルが利用不可または非推奨です。カタログと代替モデルを確認し、一時的な障害なら再試行してください。 |
| 503 | `PROVIDER_UNAVAILABLE` | プロバイダーへの経路が利用できません。間隔と回数の上限を設けて再試行してください。 |
| 503 | `UPSTREAM_ERROR` | 上流の障害です。間隔と回数の上限を設けて再試行してください。 |
| 503 | `UPSTREAM_TIMEOUT` | 上流がタイムアウトしました。間隔と回数の上限を設けて再試行してください。 |
| 503 | `UPSTREAM_UNREACHABLE` | 上流に接続できません。間隔と回数の上限を設けて再試行してください。 |

### Consoleとチェックアウト

以下はアカウント／チェックアウトのコードで、`/v1/*` の推論エラーとは別です：

| HTTP | コード | 意味と対処 |
|---|---|---|
| 403 | `API_KEY_NOT_ALLOWED` | Consoleのアカウント用エンドポイントにAPIキーを使っています。Consoleのログインセッションを使ってください。 |
| 409 | `CONFLICT` | 現在の状態と操作が競合しています。状態を再取得してから再試行してください。 |
| 424 | `CHECKOUT_FAILED` | 決済プロバイダーが請求を作成できませんでした。メッセージと取引を確認してから再作成してください。 |
| 424 | `BANK_BUSY` | iPaymuの銀行／チャネルが混雑しています。チェックアウトで別の銀行を選んでください。 |

## 再試行とストリーミング

`Retry-After` は待機秒数、`retry-after-ms` はミリ秒です。ヘッダーがない場合はジッター付き指数バックオフと試行回数の上限を使ってください。同じ組織内でキーやメンバーアカウントを増やしても共有クォータは増えません。[使用量と上限](/ja/usage-and-limits)を参照してください。

SSE開始後の失敗はストリーム内のエラーイベントで送られ、開始時のHTTPステータスは変わりません。Chat Completionsの例：

```text
data: {"error":{"code":"MODEL_AT_CAPACITY","message":"The model is at capacity right now. Please retry shortly.","type":"upstream_error","retry_after_ms":4000}}
```

ゲートウェイが処理したストリーム障害の後に `[DONE]` は追加されません。エラーイベントなしで接続が切れる場合もあります。`[DONE]` や切断だけで成功とは判断せず、エラーイベントとリクエストログを確認してください。[Messages](/ja/anthropic-messages)と[Responses](/ja/responses)で各イベント形式を確認してください。

報告には、取得できた場合の `x-request-id`、発生時刻、エンドポイント、モデル、HTTPステータス、シークレットを除いたエラー本文を添えてください。[サポート](/ja/support)を参照してください。
