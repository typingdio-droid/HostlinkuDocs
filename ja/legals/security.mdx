## 1. 暗号化と機密情報の保存

Hostlinkuのウェブサイト、Console、およびAPIとの通信は、**HTTPS (TLS)**によって保護されています。認証情報は、その種類に応じて保護されます：

- **アカウントのパスワード**は、元の形式（*プレーンテキスト*）では保存されません。
- **顧客のAPIキー**は、復元可能なキーとしてではなく、検証用の**SHA-256**ハッシュとして保存されます。
- **統合用認証情報**（アップストリームプロバイダーのキーやSSOシークレットなど）は、アプリケーションレベルで**AES-256-GCM**を使用して暗号化されます。暗号化キーはアプリケーション環境の設定から取得され、データベース内の暗号化された値とは分離されています。

## 2. アカウント認証

HostlinkuのIDサービスは、`auth2.hostlinku.com`を通じて、業界標準のIDフェデレーションプロトコルである**OpenID Connect (OIDC)**および**OAuth 2.0**を利用して利用可能です。認証フローには**PKCE S256**が使用されます。 ログイン、メール認証、および有効化されたSSOオプションは、このサービスを通じて管理されます。

<a id="passkey-dan-multi-factor-authentication-mfa"></a>

<a id="パスキーと多要素認証mfa"></a>

### Passkeyと多要素認証（MFA）

メールアドレスとパスワードの他に、以下の認証方法が利用可能です：

- **Passkey (FIDO2/WebAuthn)：** 公開鍵暗号に基づくパスワード不要（*passwordless*）の認証。秘密鍵は認証アプリまたはパスキープロバイダーによって管理され、認証時にサーバーへ送信されることはありません。
- **Authenticator (TOTP)：** 認証アプリによって生成される、時間ベースのワンタイムコード。
- **リカバリーコード (*recovery codes*):** 主要な認証要素が利用できない場合に、アクセスを復旧するための使い捨ての予備コード。

すべての認証方法は、**Console → Settings → Security** から管理できます。**Add passkey** を選択してパスキーを登録し、ログインページでパスキーを使用してログインするボタンを選択してください。リカバリーコードは、必要なときにいつでもアクセスできる安全な場所に保管してください。

<a id="sesi-console"></a>

### Consoleのセッション

Consoleは、サーバーに保存されたセッションと、クッキー**`hl_sid`**を通じてアクセスを検証します。 ログイン時、バックエンドはJWTクッキー**`hl_session`**も発行します。これら2つは**`HttpOnly`**および**`SameSite=Lax`**で設定されており、バックエンドが本番環境で稼働している場合は**`Secure`**が有効になります。

`HttpOnly`はページ上のJavaScriptによるクッキーへのアクセスを制限し、`Secure`はクッキーがHTTPS経由でのみ送信されることを保証し、`SameSite=Lax`はクロスサイトリクエストにおけるクッキーの送信を制限します。

停止されたアカウントは、ログインもAPIの利用もできません。

## 3. APIキーの取り扱い

- Keyは作成時に一度だけ完全に表示され、再度確認することはできません。
- Keyにはサービスモード、有効期間、およびクレジット制限があり、Consoleから無効化できます。現在のフォームでは、エンドポイントのスコープは提供されていません。
- ボディロギングが有効な場合、資格情報フィールドは保存前にフィルタリングされます。プロンプト内の機密情報は自動的にフィルタリングされません。
- アップストリームプロバイダーのIDおよびアップストリームの認証情報は、顧客に送信されることはありません。

## 4. 分離とアクセス制御

- リクエスト、ログ、残高、およびAPIキーへのアクセスは、権限を持つユーザー、組織、およびロールに基づいて確認されます。
- 管理者機能は管理者ロールに限定されており、ボディロギングの有効化や残高の調整など、機密性の高い設定の変更はすべて監査ログに記録されます。
- リクエストおよびレスポンスの内容はデフォルトでは保存されません。ボディロギングが有効になっている場合、内容は保持期間に応じて自動的に削除されます。[プライバシーポリシー](/ja/legals/privacy-policy)をご参照ください。

<a id="5-perlindungan-layanan"></a>

## 5. サービスの保護

- ボットやボリューム型攻撃を軽減するため、パブリックトラフィックはCloudflareを経由します。
- 組織ごとの共有クォータおよびIPごとのリクエスト制限については、[使用状況と制限](/ja/usage-and-limits)で説明されています。
- リクエストが転送される前に残高を予約することで、利用可能な残高を大幅に超える使用を防ぐことができます。
- モデルおよびアップストリームの健全性モニタリングは、[ステータス](https://status.hostlinku.com)ページで公開されています。

<a id="audit"></a>

<a id="6-audit-log"></a>

## 6. 監査ログ

ログイン、ログアウト、登録、APIキーの作成および無効化、設定の変更といったセキュリティイベントを、日時、IPアドレス、ユーザーエージェントとともに記録しています。機密情報は一切記録されません。

<a id="tanggung-jawab"></a>

<a id="7-tanggung-jawab-bersama"></a>

## 7. 共同責任

<Callout title="注記" type="note">

アカウントのセキュリティは、あなた自身にも依存します：

- 強力で一意なパスワードを使用してください；
- APIキーはサーバー側に保存し、フロントエンドのコードやリポジトリには保存しないでください；
- アプリケーションや環境ごとに個別のキーを使用し、クレジット制限を設定し、使用されていないキーを無効化してください；
- コンソールでログとトランザクション履歴を監視し、不自然な使用状況を検出してください。

</Callout>

## 8. インシデントへの対応

セキュリティインシデントが発生した場合、当社は特定、封じ込め、復旧、および評価を行います。インシデントにより個人情報の保護に失敗した場合は、PDP法（個人情報保護法）の規定に従い、影響を受けたユーザーおよび当局に通知します。APIキーの漏洩を検出した場合、当社は当該キーを無効化し、所有者に通知します。

## 9. 脆弱性の報告

[halo@hostlinku.com](mailto:halo@hostlinku.com) 宛てに、発見した問題の説明、再現手順、および影響を記載したレポートを送信してください。5営業日以内に受領確認を行います。

テストの安全性を確保するために：

- テストは、ご自身のアカウントとデータのみで行ってください；
- 他のユーザーのデータにアクセス、変更、または削除を行わないでください；
- スタッフやユーザーに対して、サービス拒否攻撃、スパム、ソーシャルエンジニアリングを行わないでください。
- 調査結果を公表する前に、修正するための妥当な期間をください。

善意に基づき、本ガイドラインに従って報告を行う研究者に対しては、法的措置を講じることはありません。
