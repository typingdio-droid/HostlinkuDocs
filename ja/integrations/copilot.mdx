[GitHub Copilot](https://docs.github.com/en/copilot)は、
一部のインターフェースで**BYOK (Bring Your Own Key)**をサポートしています。独自の*base URL*を受け付ける場所では、それを
Hostlinku へリダイレクトし、Hostlinku の残高を使用してカタログ内のモデルを利用できます。

| Copilotのインターフェース | Hostlinkuへのリンクを貼っていただいてもよろしいでしょうか？ | ガイド |
|---|---|---|
| **Copilot CLI** (`copilot`) | はい - 環境変数 `COPILOT_PROVIDER_*` | [以下](#copilot-cli) |
| **GitHub Copilot アプリ** (デスクトップ) | はい - *設定 → モデルプロバイダー* (パブリックプレビュー) | [以下](#github-copilot-app) |
| **VS CodeのCopilot Chat** | はい - プロバイダー *カスタムエンドポイント* | [VS Code](/ja/integrations/vscode) |
| JetBrains、Visual Studio、XcodeのCopilot；インラインオートコンプリート | いいえ - base URLの設定はありません | [制限事項](#batasan) |

## Copilot CLI

BYOK変数が設定されている場合、Copilot CLIはすべてのモデルリクエストをあなたのプロバイダーに送信します。**このモードでは、
GitHubへのログインは必須ではありません**。

<Steps>

<a id="set-environment-variable"></a>

### 環境変数を設定する

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # API key Hostlinku
export COPILOT_PROVIDER_BASE_URL=https://api.hostlinku.com/v1
export COPILOT_PROVIDER_API_KEY="$HOSTLINKU_API_KEY"
export COPILOT_MODEL=claude-sonnet-4-6
```

`COPILOT_PROVIDER_TYPE`のデフォルトは`openai`（Chat Completions）であるため、設定する必要はありません。Copilotは
`/chat/completions`を自動的に追加するため、ベースURLは`/v1`までで十分です。

<a id="disarankan-beri-tahu-batas-token-model"></a>

<a id="推奨モデルのトークン制限を指定する"></a>

### （推奨）モデルトークンの制限について明記してください

Copilot CLIは「Hostlinku」というスラッグを認識しないため、コンテキストが正しく切り出されるよう、[カタログ](/ja/models)から制限値を入力してください：

```bash
export COPILOT_PROVIDER_MAX_PROMPT_TOKENS=1000000
export COPILOT_PROVIDER_MAX_OUTPUT_TOKENS=64000
```

`copilot`を実行する前に、同じシェルでkeyが入力されているか確認してください。その際、値は出力しないでください：

```bash
test -n "$COPILOT_PROVIDER_API_KEY" && echo "API key tersedia" || echo "API key belum diatur"
```

<a id="jalankan"></a>

### 実行

```bash
copilot
# atau ganti model per sesi
copilot --model gpt-5-5
```

コンソールに最初に表示されるリクエスト → **リクエストログ**。

</Steps>

<a id="varian-format-anthropic"></a>

### バリエーション：Anthropic形式

Messages API（完全なプロンプトキャッシュ）経由のClaudeモデルの場合、`anthropic`プロバイダーを使用し、ベース
URLには `/v1` を**含めない**でください：

```bash
export COPILOT_PROVIDER_TYPE=anthropic
export COPILOT_PROVIDER_BASE_URL=https://api.hostlinku.com
export COPILOT_PROVIDER_API_KEY="$HOSTLINKU_API_KEY"
export COPILOT_MODEL=claude-sonnet-4-6
```

<Callout type="note" title="モデルは、ツール呼び出しとストリーミングをサポートしている必要があります">
  Copilot CLIには*tool calling*と*streaming*が必要であり、コンテキストは最低128Kトークンが推奨されます。モデルを選択する前に、[カタログ](/ja/models)でこれら3つを確認してください。
</Callout>

- **ツールやモデルに適したAPI形式を使用してください。** Chat Completionsのデフォルトプロバイダーは`openai`です。Responsesの制限については、[Responsesのリファレンス](/ja/responses)で説明されています。
- **GitHubにログインしていない場合**、GitHubサーバーに依存する機能（`/delegate`、GitHub MCPサーバー、
  コード検索）は利用できません。これらの機能が必要な場合は、`copilot login`でログインしてください。リクエストモデルは
  Hostlinkuのままです。
- **`COPILOT_OFFLINE=true`** は、GitHub へのすべての接続（テレメトリを含む）を無効にします。プロンプトは引き続き
  `api.hostlinku.com` に送信されます。

<a id="github-copilot-app"></a>

## GitHub Copilot アプリ

GitHub Copilotのデスクトップアプリは、独自のモデルプロバイダーをサポートしています（パブリックプレビュー）。GitHubへのログインは
依然として必要ですが、独自のプロバイダーのみを使用する場合は**Copilotパッケージは必要ありません**。

<Steps>

<a id="tambah-provider"></a>

<a id="プロバイダーを追加する"></a>

### プロバイダーを追加

アプリ設定 → **モデルプロバイダー** → **プロバイダーを追加** → **OpenAI互換**を選択してください。

<a id="isi-detail-provider"></a>

<a id="プロバイダーの詳細を入力してください"></a>

### プロバイダーの詳細情報

| フィールド | 値 |
|---|---|
| **表示名** | `Hostlinku` |
| **Base URL** | `https://api.hostlinku.com/v1` |
| **APIキー** | `sk-…`（HostlinkuのAPIキー） |

**Add provider**をクリックします。キーはオペレーティングシステムの資格情報ストアに保存されます。

<a id="pilih-model-per-sesi"></a>

<a id="セッションごとのモデルを選択"></a>

### セッションごとのモデルを選択してください

Hostlinkuモデルは、GitHubモデルの横にあるモデルピッカーに表示されます。エージェントセッションを開始する際に、いずれかを選択してください
。

</Steps>

Claudeモデルの場合、プロバイダーとして**Anthropic**を選択し、ベースURLに
`https://api.hostlinku.com`（`/v1`を除く）を入力することも可能です。これは、プロバイダーのフォームにベースURLの欄が表示されている場合に利用可能です。

<a id="batasan"></a>

<a id="制限"></a>

## 制限事項

- **JetBrains、Visual Studio、およびXcodeのCopilot**には、ユーザーごとのベースURLやカスタムプロバイダーの設定はありません。
  JetBrainsでは、[JetBrains AI Assistant](/ja/integrations/jetbrains)
  または [Junie CLI](/ja/integrations/junie) を使用して、Hostlinku モデルを利用してください。
- **インラインオートコンプリート（ゴーストテキスト）**は、すべてのエディタにおいて常にCopilotのインフラストラクチャを使用します。BYOK
  はチャットおよびエージェントにのみ適用されます。
- **Copilot Business/Enterprise：** 組織の管理者は、Copilotのポリシー設定でBYOK（およびCopilotアプリ用のCopilot CLI）を
  許可する必要があります。

<a id="troubleshooting"></a>

## トラブルシューティング

| 症状 | 解決策 |
|---|---|
| `401` | `copilot` を実行しているシェルで、`COPILOT_PROVIDER_API_KEY` が空または不正です。上記のチェックを行い、キーが入力されていることを確認してください。それでも拒否される場合は、コンソールから再度コピーしてください。 |
| すべてのリクエストにおける `404` | `/v1`を含まないプロバイダー `openai`、または `/v1` を含むプロバイダー `anthropic`。 |
| `404 model_not_found` | `COPILOT_MODEL`は、`GET /v1/models`のスラグと完全に一致させる必要があります。 |
| Errorモデルはツール呼び出しをサポートしていません | [カタログ](/ja/models)の「*tool calling*」モデルに変更してください。 |
| 引き続きGitHubのモデルを使用しています | 変数は他のシェルにエクスポートされます。同じシェルから `copilot` を実行するか、`~/.zshrc` に追加してください。 |
