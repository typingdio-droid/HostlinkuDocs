[Codex CLI](https://developers.openai.com/codex/cli) は OpenAI Responses を使用します。カスタム provider を [`POST /v1/responses`](/ja/responses) に設定してください。ツールと reasoning の対応はモデルと経路に依存します。

<Steps>

### Codex CLI をインストールする

```bash
npm install -g @openai/codex
# または: brew install codex
```

### プロバイダー Hostlinku を追加する

`~/.codex/config.toml` を編集してください（存在しない場合は作成してください）。このユーザーファイルではプロバイダを**必ず**定義する必要があります。セキュリティ上の理由から、プロジェクト内の `.codex/config.toml` が `model_providers` を上書きしてはなりません。

```toml
model = "gpt-5-3-codex"
model_provider = "hostlinku"
model_reasoning_effort = "medium"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

### APIキーを設定して実行する

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # simpan di ~/.zshrc / ~/.bashrc
codex
```

Codexは、`env_key`で指定された変数からキーを読み取ります。このキーは、`config.toml`には決して書き込まれません。

<Callout type="tip" title="GUI でワンクリック管理したい場合">
  デスクトップアプリ [CC Switch](/ja/integrations/cc-switch) を使用すると、`config.toml` を手動で編集することなく Codex のプロバイダーやモデルを視覚的に切り替えられます。
</Callout>

### 確認

簡単な指示を1つ送信してください（例：*「このリポジトリの構造を説明してください」*）。リクエストはコンソールの → **リクエストログ** に、モデル `gpt-5-3-codex` として表示されます。Codex を開く前にエンドポイントを確認したい場合は：

```bash
curl https://api.hostlinku.com/v1/responses \
  -H "Authorization: Bearer $HOSTLINKU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "gpt-5-3-codex", "input": "Halo" }'
```

</Steps>

## プロフィールに表示されるいくつかのモデル

設定を変更せずにモデルやプロバイダーを切り替えるには、`[profiles.*]` を使用してください：

```toml
[profiles.cepat]
model = "gpt-5-6-luna"
model_provider = "hostlinku"
model_reasoning_effort = "low"

[profiles.kuat]
model = "gpt-6-astra"
model_provider = "hostlinku"
```

```bash
codex --profile kuat
codex --profile cepat "utils/date.ts のユニットテストを書いて"
```

<Callout type="warning" title="モデルとツールの互換性">
  使用中の Codex のツールを扱える Responses ネイティブモデルを使用してください。Chat Completions ブリッジはテキストと function calling に対応しますが、custom shell/patch tools と暗号化 reasoning にはネイティブ対応が必要です。`The requested tool type is not supported by this model` が出たら、モデルまたは Chat/Anthropic クライアントを変更してください。[Responses API](/ja/responses)を参照してください。
</Callout>

<Callout type="note" title="Stateless">
  履歴全体を `input` に送信し、`store: false` を使用してください。非 null の `previous_response_id` / `conversation` と `background: true` は拒否されます。暗号化 reasoning は upstream 対応が必要です。[Responses API](/ja/responses)を参照してください。
</Callout>

<Callout type="tip" title="デフォルトのOpenAIエンドポイントのみを変更したいのですか？">
新しいプロバイダーを使用しない代替案：`config.toml` および `OPENAI_API_KEY=sk-…` で `openai_base_url = "https://api.hostlinku.com/v1"` を設定する（API キー Hostlinku）。 カスタムプロバイダーは、UI上でその名称が明確であり、キーが元のOpenAIキーとは別になっているため、引き続き推奨されます。
</Callout>

## トラブルシューティング

- **`401`** - `env_key` の変数が、`codex` が実行されているシェルにはエクスポートされていません。
- **shell/patch ツールが動かない** — モデルと Responses 経路のツール対応を確認してください。テキスト回答だけではツール実行を証明できません。
- **`400 previous_response_id`** — `previous_response_id` / `conversation` を削除し、履歴全体を `input` に送り、`store: false` を使用してください。
- **モデルが表示されない / `404`** - slugが間違っています。`/v1/models` には、あなたのキーに対応する有効なリストが表示されます。
- **古いクライアント** — Codex を更新し、[公式設定リファレンス](https://developers.openai.com/codex/config-reference/)に従って `wire_api = "responses"` を使用してください。
