[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`) は、DeepSeekが提供する
オープンソースのコーディングエージェントです。 選択した作業フォルダ内で、`dsh`はファイルの読み取り、コードの編集、
シェルコマンドの実行、および多段階のタスクの実行が可能です。これらは、Webインターフェース、
ヘッドレスモード、SDK、またはACPを通じて行われます。

`dsh`は**Anthropic Messages**プロトコルを使用します。Hostlinkuはこれを
[`POST /v1/messages`](/ja/anthropic-messages)で提供しているため、`dsh`は
2つの環境変数だけでHostlinkuにリダイレクトできます。プロキシも追加のプラグインも不要です。

<Callout type="note" title="テスト済みバージョン">
  このガイドは、`@deepseek-ai/dsh` **0.2.1-rc.5** を使用してエンドツーエンドで検証されています（エージェントがツールを通じてファイルを読み込み
  、応答するヘッドレスモード）。DeepSeek Harness はまだ *開発プレビュー* 段階であり、ファイル名
  やパラメータの挙動は、次のバージョンで変更される可能性があります。
</Callout>

<a id="始める前に"></a>

## 開始する前に

- **最新のNode.js LTS** (`node --version`)。`dsh` パッケージは数百もの依存関係を呼び出すため、
  初回インストールには1～3分かかる場合があります。
- **HostlinkuのAPIキー** [console.hostlinku.com](https://console.hostlinku.com) の `sk-…` → **API Keys**。
- **残高**、またはそのキーに対して十分なクレジット限度額。
- **安全なテスト用フォルダ。** `dsh` を実行するフォルダがデフォルトのワークスペースとなります。
  ホームディレクトリや重要なデータが含まれるフォルダから直接実行しないでください。

<Steps>

<a id="instal-deepseek-harness"></a>

<a id="deepseek-harness-をインストールする"></a>

### DeepSeek Harnessをインストールする

```bash
npm install -g @deepseek-ai/dsh
dsh --version
```

または、グローバルインストールを行わずに実行してください：`npx @deepseek-ai/dsh web`。

<a id="arahkan-ke-hostlinku"></a>

<a id="hostlinku-に接続する"></a>

### Hostlinkuへ誘導してください

`dsh`は、エンドポイントを`DEEPSEEK_BASE_URL`から、APIキーを`DEEPSEEK_API_KEY`から読み取ります。

**macOS / Linux / WSL**（`~/.zshrc` または `~/.bashrc` に保存）：

```bash
export DEEPSEEK_BASE_URL=https://api.hostlinku.com
export DEEPSEEK_API_KEY=sk-your-api-key
```

**Windows PowerShell:**

```powershell
$env:DEEPSEEK_BASE_URL = "https://api.hostlinku.com"
$env:DEEPSEEK_API_KEY  = "sk-your-api-key"
```

`dsh`は独自に`/v1/messages`を追加します。ベースURL `https://api.hostlinku.com/v1`も受け入れられます
（接尾辞`/v1`は再利用され、重複しません）。

<a id="pilih-model-dan-batas-output"></a>

<a id="モデルと最大出力トークンを設定する"></a>

### 出力形式と制限を選択してください

組み込みモデル `dsh` (`deepseek-flash`) は Hostlinku のスラッグではなく、`dsh` はデフォルトで `max_tokens: 256000`
を送信します。これは、ほとんどのモデルの出力制限を超えています。 これらはいずれも、ホームディレクトリのパッチファイル
`~/.dsh/cordis.patch.yml`（または、`DSH_HOME`が設定されている場合は`$DSH_HOME/cordis.patch.yml`）で設定されます。

```yaml
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-v4-flash
- id: llm-deepseek
  config:
    apiKeyEnv: DEEPSEEK_API_KEY
    maxTokens: 32000
```

<Callout type="important" title="Patchは設定ブロック全体を置き換えます">
  Patchではフィールドを一つずつ結合しません。Patch内の`config`ブロックは、
  を置き換えます。そのため、`provider: deepseek-official` および `apiKeyEnv` は記述したままにする必要があります。そうしないと、`dsh`
  は `$.provider missing required value` というエラーで起動に失敗します。
</Callout>

<a id="jalankan"></a>

<a id="実行する"></a>

### 実行

ヘッドレスモードによるクイックテスト（1つのタスクを実行し、最終的な回答を出力してから終了）：

```bash
mkdir dsh-test && cd dsh-test
echo "the secret word is PINEAPPLE" > hello.txt
dsh --profile headless "Read hello.txt and reply with only the secret word."
```

正しい出力：`PINEAPPLE`。これは、エージェントがHostlinkuを介してファイル読み取りツールを正常に呼び出し、
応答したことを意味します。ブラウザでの完全なインターフェースについては：

```bash
dsh web
```

<a id="verifikasi"></a>

<a id="確認する"></a>

### 検証

コンソールを開き、**リクエストログ**を選択してください。`dsh`からのリクエストは、選択したモデル、トークン数
、コスト、および使用されたAPIキーとともに表示されます。

</Steps>

<a id="model-yang-direkomendasikan"></a>

<a id="おすすめのモデル"></a>

## 推奨されるモデル

`model`フィールドには、ツール呼び出しをサポートする[カタログ](/ja/models)内の任意のスラグを入力できます。
あなたのキーに対して有効なリストは、`GET /v1/models`にあります。

| 要件 | Slug | 注記 |
|---|---|---|
| デフォルトは日次、高速かつ低コスト | `deepseek-v4-flash` | コンテキスト：1M、推論、ツール呼び出し。 |
| 画像（スクリーンショット、図）の提供が必要です | `deepseek-v4-1-flash` | ビジョンを支持する。 |
| 大規模な作業／大規模なリファクタリング | `deepseek-v4-pro` | コンテキスト1M、より深い考察。 |
| open-weightの代替案 | `kimi-k2-7-code`、`glm-5-3` | ツール呼び出しと推論。 |

<Callout type="tip" title="maxTokensはモデルに合わせて調整してください">
  `maxTokens`はリクエストごとの出力制限であり、コンテキストのサイズではありません。例中の値`32000`は初期設定であり、モデルの最大値ではありません。モデルの出力制限については[カタログ](/ja/models)で確認してください。制限が記載されていない場合は、リクエストが拒否された際にその値を小さくしてください。
</Callout>

<a id="keamanan"></a>

## セキュリティ

- タスクの実行中、プロンプト、コードスニペット、ファイルの内容、およびツールの結果は、推論のためにHostlinkuに送信されます。
  営業秘密や個人データを含むプロジェクトでは、許可なく`dsh`を実行しないでください。
- 漏洩時に簡単に無効化できるよう、クレジット制限付きの`dsh`専用の**個別のAPIキー**を使用してください。
  [認証](/ja/authentication)を参照してください。
- `cordis.patch.yml` に API キーを直接記述しないでください。`apiKeyEnv` には変数の**名前**のみを保存します。
  キーの値は引き続き環境変数から読み込まれます。

<a id="troubleshooting"></a>

## トラブルシューティング

| 症状 | 原因と解決策 |
|---|---|
| `INVALID_REQUEST: max_tokens (256000) exceeds the output limit of model …` | `maxTokens` はまだ設定されていません。`llm-deepseek` ブロックに `maxTokens: 32000` を追加してください。 |
| `startup failed … $.provider missing required value` | パッチ内の `agent-default-model` ブロックには `provider` が含まれていません。上記の例のように完全に書き直してください。 |
| `MISSING_CREDENTIAL` | `DEEPSEEK_API_KEY`は、`dsh`が実行されているシェルではまだエクスポートされていません。 |
| `401` / *無効なAPIキー* | キーが不正、無効化、または期限切れです。コンソールで新しいキーを作成してください。 |
| `404 model not found` | スラグが間違っているか、依然として `deepseek-flash` となっています。`GET /v1/models` からスラグをコピーしてください。 |
| 画像の添付に失敗しました | `dsh`は、まず`/v1/files`経由で画像をアップロードしようと試み、その後自動的に画像をインラインで再送信します。選択したモデルがビジョンに対応していることを確認してください（例：`deepseek-v4-1-flash`）。 |
