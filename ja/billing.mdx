Hostlinkuではプリペイドクレジットを使用します。**1 <CreditIcon /> = $1**。組織の残高は関連するAPIキーで共有され、サービスクレジットとなります。返金については[返金ポリシー](/ja/legals/refund-policy)に従います。

<a id="チャージ"></a>

## 組織の残高を追加する

1. [Console](https://console.hostlinku.com) → **Billing** → top-up を開いてください。
2. 金額またはプリセットを選択し、続いて支払い方法を選択してください。
3. VAについては銀行を、暗号資産についてはコイン／ネットワークを選択してください。
4. 合計額、ボーナス、為替レート、および料金を確認し、指示に従って支払いを行ってください。支払いが確認されると、クレジットが自動的に付与されます。

| 方法 | プロバイダー | ページ |
|---|---|---|
| QRIS | iPaymu Direct | Hostlinku Pay、QRルピア |
| Virtual Account | iPaymu Direct | Hostlinku Pay、銀行の仮想口座番号 |
| Crypto | Heleket | Heleketの支払いページ |

「最小」、「最大」、および利用可能な方法は、支払い概要に従ってください。暗号資産による支払いの請求書はデフォルトで**20分**間有効ですが、プロバイダーがこれを延長する場合があります。リンクの有効期限は支払い期限とは異なります。表示されている期限に従い、リンクが無効になった場合は、Billingから取引を再度開いてください。

Payのリンクは、1回の取引に限りログインなしで開くことができます。リンクは個人で保管してください。NOWPayments/BlockBeeのリンクは、過去の取引にまだ表示される場合があります。

<a id="biaya-penggunaan"></a>

<a id="利用費用"></a>

## 利用料金

価格はモデルおよび**Service Mode key**によって異なります。[モデルカタログ](/ja/models)、Consoleの**Models**、または使用するキーを指定して`GET /v1/models`を確認してください。

| ディメンション | 単価 |
|---|---|
| 入力、出力、キャッシュの読み取り／書き込み | 100万トークンあたり |
| Web検索（利用可能な場合） | 1,000コールあたり |

Token cacheは入力に含まれ、通常の入力として再度カウントされることはありません。Billingではupstream usageを使用します。usageが利用できない場合、費用は推定値を使用することができます。

- **非ストリーミングチャット**：コストは `hostlinku.cost` に表示されます。
- **SSEストリーミング**：ストリーミング完了後、**ログ／アナリティクス／請求**で最終的な費用を確認してください。

<a id="利用可能残高とキー上限"></a>

## 利用可能残高とキーの制限

`available = balance − reserved`。残高の一部は、実行中のリクエストのために一時的に予約されます。リクエストが完了すると、利用料金が計算され、残りの予約分は解放されます。

Top-upは組織の残高を追加するものであり、**Monthly Spending Limit**キーではありません。`402 PAYMENT_REQUIRED`を受け取った場合は、メッセージを確認してください：残高が不足している場合は補充するか、上限に達している場合はリセットを待つか、上限を変更してください。詳細は[認証](/ja/authentication)をご覧ください。

<a id="transaksi-dan-invoice"></a>

## 取引と請求書

**Billing**を開くと、取引履歴や支払済みのチャージ請求書を確認できます。ブラウザから印刷またはPDFとして保存してください。Payリンクからの請求書には、有効なリンクと支払済みの取引が必要です。

**Billing Profile**はブラウザに保存され、Consoleからの請求書の印刷結果に影響を与えます。このプロファイルは他のデバイスや請求書サーバーとはまだ同期されていません。Payの請求書には異なる詳細が表示される場合があります。

Consoleで残高を確認してください。自動リチャージの設定および残高不足時のメール通知は、現在の課金フローではまだ利用できません。

<a id="biaya-historis-dan-rincian-analytics"></a>

<a id="過去の料金とanalyticsの内訳"></a>

## 過去の費用および分析の詳細

請求済みのリクエストの総費用はログに保存されます。入力/出力/キャッシュの詳細の一部は現在の料金に基づいて再計算されるため、その詳細は過去の合計とは異なる場合があります。詳細の表示変更によって、過去のリクエストが再請求されることはありません。
