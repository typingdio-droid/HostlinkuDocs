Prompt cachingは、同じprefixの処理費用を減らせる仕組みです。対応状況、最小トークン数、有効期間、価格はモデルとプロバイダーに依存します。同じプロンプトを再送してもキャッシュヒットは保証されません。

## 価格と使用量

利用するAPIキーで [`GET /v1/models`](/ja/models) の `pricing.cache_read` と `pricing.cache_write` を確認してください。価格はキーのService Modeに従い、100万トークン単位です。未設定の価格は省略される場合があります。キャッシュ書き込みは通常の入力より高いことがあり、節約額はトークン数とその後のヒット回数に依存します。

Consoleの **Logs** はInput、Output、Cache Read、Cache Write、最終費用を表示します。Cache Write 5m/1hの内訳は上流が返した場合だけ記録され、`-` はゼロではなく情報がないことを示します。過去の費用内訳の一部は現在の単価で計算されますが、過去の合計は保存されています。[Billing](/ja/billing)を参照してください。

## プロンプトの配置

静的な内容を先に置きます。ツール定義、system prompt／文書、過去のメッセージの順にし、最新のユーザーメッセージや変化する値を後に置いてください。タイムスタンプやツールの順序など、prefixの変更でキャッシュミスが起こる場合があります。

対応経路のClaudeでは、静的ブロックに `cache_control` を付けます。この指定だけでヒットするわけではなく、モデルと上流の条件を満たす必要があります。

## Anthropic Messages

`system` ブロックに `cache_control` を付ける例です：

```bash
curl https://api.hostlinku.com/v1/messages \
  -H "x-api-key: sk-your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "system": [{
      "type": "text",
      "text": "<変更しない長い指示と参考文書>",
      "cache_control": {"type": "ephemeral"}
    }],
    "messages": [{"role": "user", "content": "第3節を要約してください。"}]
  }'
```

キャッシュ書き込み時の `usage` の例：

```json
{
  "usage": {
    "input_tokens": 16,
    "cache_creation_input_tokens": 3601,
    "cache_read_input_tokens": 0,
    "output_tokens": 4
  }
}
```

`cache_creation_input_tokens` は書き込み、`cache_read_input_tokens` は読み取りのトークン数です。読み取りがゼロより大きければ、上流がキャッシュ使用を報告しています。キャッシュの条件を満たさない場合や情報がない場合、両方ともゼロになることがあります。

## OpenAI Chat Completions

Claudeモデルでは、bridgeがcontent partの `cache_control` をAnthropicブロックへ転送します：

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "system", "content": [{
        "type": "text",
        "text": "<変更しない長い指示と参考文書>",
        "cache_control": {"type": "ephemeral"}
      }]},
      {"role": "user", "content": "第3節を要約してください。"}
    ]
  }'
```

Chat Completionsの `usage.prompt_tokens` にはキャッシュトークンが含まれます。`usage.prompt_tokens_details.cached_tokens` は読み取り、`cache_write_tokens` は情報がある場合の書き込み数です。キャッシュトークンを `prompt_tokens` に再度足さないでください。

## Agentとその他のプロトコル

すでに `cache_control` を付けるアプリはHostlinku経由でも利用できますが、挙動はアプリのバージョンとモデルに依存します。[IDE・Agent統合](/ja/integrations)を参照してください。他のモデルは指定なしで上流の自動キャッシュを利用する場合がありますが、ヒットと使用量の報告はモデルごとに異なります。

`/v1/responses` のChat Completions bridgeは、現在 `cache_control` の明示指定を提供していません。native／上流経路の自動キャッシュと報告されるトークン数はモデルに依存します。上記のClaude指定には `/v1/messages` または `/v1/chat/completions` を使ってください。

## ヒットの確認

1. モデルの条件を満たすプロンプトを送り、**Logs** のCache Write/Readを確認します。
2. 上流のキャッシュ有効期間内に同じprefixを再送し、Cache Readを確認します。
3. 同じモデル、Service Mode、出力の長さで比較します。出力トークン数も費用差に影響します。

Cache Readがゼロのままなら、prefix、ブロックサイズ、モデル対応、有効期間を確認してください。使用量の情報が想定と違う場合は[サポート](/ja/support)を参照してください。
