プロンプトのキャッシュにより、繰り返されるプレフィックスの処理コストを削減できます。サポート、トークンのしきい値、有効期間、およびキャッシュのレートは、モデルおよびプロバイダーによって異なります。プロンプトが再送信されたからといって、キャッシュヒットが保証されるわけではありません。

<a id="harga-dan-penggunaan"></a>

<a id="価格と使用量"></a>

## 価格と利用状況

使用するAPIキーで、[`GET /v1/models`](/ja/models) における `pricing.cache_read` および `pricing.cache_write` を確認してください。価格はサービスモードのキーに基づいており、100万トークンごとに計算されます。利用できない料金については記載されない場合があります。 キャッシュへの書き込みは通常の入力よりもコストが高くなる可能性があるため、コスト削減効果はトークンの数やその後のキャッシュヒット率によって異なります。

Consoleの**ログ**には、入力、出力、キャッシュ読み取り、キャッシュ書き込み、および最終的な費用が表示されます。キャッシュ書き込みの詳細（5分/1時間）は、アップストリームから報告があった場合にのみ表示されます。`-`は、詳細が利用できないことを意味し、ゼロではないことを示します。 過去の履歴については、一部の費用内訳に現在の料金が適用されていますが、過去の合計額は引き続き保存されています。[Billing](/ja/billing)を参照してください。

<a id="menyusun-prompt"></a>

<a id="プロンプトの配置"></a>

## プロンプトの作成

静的なコンテンツを先に配置してください：ツールの定義、システムプロンプト／ドキュメント、そして古いメッセージの順です。最新のユーザーメッセージや変更された値は、その後に配置してください。プレフィックスの変更（タイムスタンプやツールの順序を含む）は、キャッシュミスを引き起こす可能性があります。

Claudeが対応している環境では、静的ブロックに`cache_control`を設定してください。この指定はキャッシュヒットを強制するものではありません。ブロックは引き続き、モデルおよびアップストリームの要件を満たす必要があります。

## Anthropic Messages

以下の例では、`system`ブロック内で`cache_control`を使用しています：

```bash
curl https://api.hostlinku.com/v1/messages \
  -H "x-api-key: sk-your-api-key" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "system": [{
      "type": "text",
      "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
      "cache_control": {"type": "ephemeral"}
    }],
    "messages": [{"role": "user", "content": "Ringkas bagian 3."}]
  }'
```

キャッシュ書き込み時の `usage` の例：

```json
{
  "usage": {
    "input_tokens": 16,
    "cache_creation_input_tokens": 3601,
    "cache_read_input_tokens": 0,
    "output_tokens": 4
  }
}
```

`cache_creation_input_tokens`はキャッシュ書き込みをカウントし、`cache_read_input_tokens`はキャッシュ読み取りをカウントします。ゼロより大きい読み取り値は、アップストリームから報告されたキャッシュの使用を示します。リクエストがキャッシュの条件を満たさない場合、またはキャッシュ情報が利用できない場合は、両方がゼロになることがあります。

<a id="openai-chat-completions"></a>

## OpenAIチャット補完

Claudeモデルでは、ブリッジがコンテンツパートの`cache_control`をAnthropicブロックに転送します：

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "system", "content": [{
        "type": "text",
        "text": "<instruksi panjang dan dokumen referensi yang tidak berubah>",
        "cache_control": {"type": "ephemeral"}
      }]},
      {"role": "user", "content": "Ringkas bagian 3."}
    ]
  }'
```

「Chat Completions」形式では、`usage.prompt_tokens`にはキャッシュトークンが含まれています。`usage.prompt_tokens_details.cached_tokens`はキャッシュの読み取りを、`cache_write_tokens`はキャッシュの書き込み（利用可能な場合）をカウントします。キャッシュトークンを`prompt_tokens`に再度加算しないでください。

<a id="agentとその他のプロトコル"></a>

## エージェントおよびその他のプロトコル

`cache_control` を設定済みのアプリケーションは、Hostlinku にリダイレクトされた際にこれを利用できます。動作はアプリケーションのバージョンやモデルによって異なります。[IDE およびエージェントの統合](/integrations) を参照してください。他のモデルでは、この設定なしでもアップストリームの自動キャッシュを利用できますが、ヒット数やレポートはモデルごとに異なります。

`/v1/responses` は、Chat Completions ブリッジにおいて `cache_control` の明示的なマーカーをまだ提供していません。自動キャッシュおよびネイティブ/アップストリームから報告されるキャッシュトークンは、引き続きモデルに従います。上記の例における Claude のマーカーについては、`/v1/messages` または `/v1/chat/completions` を使用してください。

<a id="ヒットの確認"></a>

## キャッシュヒットの確認

1. モデル要件を満たすプロンプトを送信し、**Logs**でキャッシュの書き込み/読み取りを確認してください。
2. アップストリームのキャッシュ期間内に同じプレフィックスを送信し、Cache Readが設定されているか確認してください。
3. 「request」を、モデル、サービスモード、および出力長が同じものと比較してください。コストの差は、キャッシュだけでなく、出力トークンにも影響されます。

Cache Readがゼロのままの場合は、プレフィックス、ブロックサイズ、モデルのサポート状況、およびキャッシュの有効期間を確認してください。使用状況に関する情報が一致しない場合は、[ヘルプ](/ja/support)を参照してください。
