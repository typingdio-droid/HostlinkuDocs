Kode berikut memakai format Chat Completions. Messages dan Responses memiliki format error sendiri; lihat [Error](/errors) untuk referensi lengkap.

## 401 UNAUTHORIZED

Periksa nilai dan status key di Console → **API Keys**. Endpoint gateway menerima `Authorization: Bearer sk-...` atau `x-api-key`. Jangan mengulang request dengan key yang sama jika key salah, nonaktif, atau kedaluwarsa.

## 402 PAYMENT_REQUIRED

Baca pesan error: isi saldo organisasi jika saldo tersedia kurang, atau ubah limit kredit key/tunggu reset jika limit tercapai. Top-up tidak menaikkan limit key. Lihat [Billing & Saldo](/billing).

## 404 MODEL_NOT_FOUND

Slug model tidak ada di katalog. Ambil slug persis dari `GET /v1/models` atau halaman [Model](/models). Jangan menebak slug dari nama tampilan.

## 400 MODEL_NOT_IN_SERVICE_MODE

Model ada, tetapi tidak tersedia untuk Service Mode API key yang dipakai. Contoh: key Low-Cost memanggil model yang hanya punya rute Performance. Buat key dengan mode yang sesuai atau pilih model lain.

## 422 VALIDATION_FAILED

Perbaiki field yang disebut pada `details.issues`, misalnya `messages` kosong atau tipe field salah. Status 422 berlaku untuk validasi Chat Completions; Messages dan Responses memakai 400. Lihat [contoh request](/chat-completions).

## 429 RATE_LIMITED

Kuota Service Mode dipakai bersama organisasi. Tunggu sesuai `Retry-After`, gunakan backoff, dan kurangi burst. Request yang ditolak limiter tidak memotong saldo. Detail ada di [Pemakaian & Limit](/usage-and-limits).

## 503 MODEL_UNAVAILABLE / UPSTREAM_ERROR

Model sedang deprecated/tidak tersedia, atau upstream mengalami gangguan sementara. Untuk `UPSTREAM_ERROR`, coba lagi beberapa saat. Untuk `MODEL_UNAVAILABLE`, cek pesan error apakah ada `replacement_slug`.

<Callout type="note" title="Tips debugging">
  Simpan `x-request-id` dari header respons. ID itu bisa dipakai untuk mencocokkan request dengan log di Console saat menghubungi dukungan.
</Callout>
