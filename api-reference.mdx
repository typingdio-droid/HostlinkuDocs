Gunakan API key untuk endpoint gateway. Endpoint akun Console pada `/api/*` memakai sesi login. Dukungan parameter, vision, reasoning, cache, dan tool calling mengikuti model serta jalur protokolnya.

| Endpoint | Kegunaan | Panduan |
|---|---|---|
| `GET /v1/models` | Katalog untuk Service Mode key | [Models](/models) |
| `POST /v1/chat/completions` | Chat dan streaming SSE | [Chat Completions](/chat-completions) |
| `POST /v1/messages` | Pesan format Anthropic | [Anthropic Messages](/anthropic-messages) |
| `POST /v1/messages/count_tokens` | Hitung token format Anthropic tanpa biaya | [Count tokens](/anthropic-messages) |
| `POST /v1/responses` | Responses stateless | [Responses API](/responses) |

## Base URL dan autentikasi

OpenAI SDK memakai `https://api.hostlinku.com/v1`; Anthropic SDK memakai `https://api.hostlinku.com`. Gateway menerima `Authorization: Bearer sk-your-api-key` atau `x-api-key`. Lihat [Autentikasi](/authentication).

## Kompatibilitas model dan tool

Slug yang muncul di katalog key dapat dipakai pada endpoint yang didukung. Kompatibilitas format tidak menjamin seluruh fitur setiap klien. Periksa batas [Responses](/responses) dan [integrasi yang dipakai](/integrations).

## Kuota bersama organisasi

Setiap Service Mode memiliki kuota **600 request, 6.500.000 token input, dan 200.000 token output per menit**, dipakai bersama semua API key dan anggota organisasi. Login, Console, dan checkout memiliki batas per IP tersendiri. [Pemakaian & Limit](/usage-and-limits).

## Error Codes

Format error mengikuti endpoint; kegagalan sebelum handler dapat memakai envelope umum Hostlinku. Daftar kode dan cara menangani kegagalan tersedia di [Error](/errors). Format khusus ada di [Anthropic Messages](/anthropic-messages#format-error) dan [Responses](/responses#format-error).

## Query Available Models

`GET /v1/models` mengembalikan model dan harga untuk Service Mode key. Katalog situs memakai `GET /api/public/models-v2`. Lihat [Model](/models) untuk daftar, kapabilitas, dan cara membaca tarif.

## Biaya dan streaming

Respons chat non-streaming memuat `hostlinku.cost` dan `hostlinku.latencyMs`. Setelah streaming selesai, periksa biaya di Logs / Analytics / Billing; jangan mengharapkan biaya pada setiap chunk. Catat `x-request-id` jika tersedia. [Billing & Saldo](/billing).

## Arti metrik dan contoh angka

| Metrik | Arti |
|---|---|
| `hostlinku.latencyMs` | Waktu dari request diterima gateway sampai respons selesai. |
| TTFT | Waktu sampai token pertama teramati pada stream; dapat kosong pada non-streaming. |
| TPS | Token output per detik setelah token pertama, dari sampel stream yang memenuhi syarat. |

- **Animasi landing** memakai angka contoh yang tetap; angka animasi tidak berasal dari request inferensi pada saat diputar.
- **Grafik 60 batang pada detail model** dibentuk dari agregat rata-rata/P95 latensi dan jumlah kegagalan. Setiap batang merupakan visualisasi sintetis, bukan satu request atau probe berurutan. Grafik pemakaian Console menggunakan agregat data request.
- **Badge footer landing** memakai status tetap; periksa [Status](https://status.hostlinku.com) untuk hasil pemantauan dan insiden.
- **Reachable** berarti respons HTTP di bawah 500, termasuk 401/403/404. Pemeriksaan ini menunjukkan keterjangkauan endpoint; keberhasilan login dan inferensi diperiksa melalui fungsi masing-masing.

Bandingkan metrik dari periode, Service Mode, dan sampel yang sama. Hasil animasi, spesifikasi kapasitas, agregat trafik, dan benchmark memiliki sumber yang berbeda.
