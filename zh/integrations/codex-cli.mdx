[Codex CLI](https://developers.openai.com/codex/cli) 使用 OpenAI Responses。将自定义 provider 指向 [`POST /v1/responses`](/zh/responses)；工具与 reasoning 兼容性取决于模型及 Responses 路径。

<Steps>

### 安装 Codex CLI

```bash
npm install -g @openai/codex
# 或者: brew install codex
```

### 添加提供商 Hostlinku

编辑 `~/.codex/config.toml`（若不存在则创建）。该用户文件中**必须**定义提供程序-出于安全考虑，项目中的 `.codex/config.toml` 不得覆盖 `model_providers`。

```toml
model = "gpt-5-3-codex"
model_provider = "hostlinku"
model_reasoning_effort = "medium"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

### 设置 API 密钥并运行

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # simpan di ~/.zshrc / ~/.bashrc
codex
```

Codex 从名为 `env_key` 的变量中读取键；该键从未写入 `config.toml`。

<Callout type="tip" title="想要使用图形界面一键切换？">
  使用桌面应用 [CC Switch](/zh/integrations/cc-switch)，无需手动编辑 `config.toml` 即可可视化添加和切换 Codex 提供商与模型。
</Callout>

### 验证

发送一条简单的指令（例如 *“说明此仓库的结构”*）。该请求将显示在控制台的 → **请求日志** 中，模型编号为 `gpt-5-3-codex`。如果想在打开 Codex 之前确认端点：

```bash
curl https://api.hostlinku.com/v1/responses \
  -H "Authorization: Bearer $HOSTLINKU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "gpt-5-3-codex", "input": "Halo" }'
```

</Steps>

## 几位模特通过个人资料

使用 `[profiles.*]` 可在无需修改配置的情况下切换模型/提供商：

```toml
[profiles.cepat]
model = "gpt-5-6-luna"
model_provider = "hostlinku"
model_reasoning_effort = "low"

[profiles.kuat]
model = "gpt-6-astra"
model_provider = "hostlinku"
```

```bash
codex --profile kuat
codex --profile cepat "为 utils/date.ts 编写单元测试"
```

<Callout type="warning" title="模型与工具兼容性">
  使用支持当前 Codex 工具的原生 Responses 模型。Chat Completions 桥接支持文本及 function calling；custom shell/patch tools 和加密 reasoning 需要原生支持。出现 `The requested tool type is not supported by this model` 时，请更换模型或使用合适的 Chat/Anthropic 客户端。见 [Responses API](/zh/responses)。
</Callout>

<Callout type="note" title="Stateless">
  在 `input` 中发送完整历史并使用 `store: false`。Hostlinku 拒绝非 null 的 `previous_response_id` / `conversation` 和 `background: true`。加密 reasoning 项目需要 upstream 支持；见 [Responses API](/zh/responses)。
</Callout>

<Callout type="tip" title="只是想替换默认的 OpenAI 端点吗？">
无需新提供商的替代方案：将 `openai_base_url = "https://api.hostlinku.com/v1"` 设置为 `config.toml` 和 `OPENAI_API_KEY=sk-…`（API 密钥 Hostlinku）。 仍建议使用自定义提供商，因为其名称在用户界面中清晰可见，且其密钥与原始密钥 OpenAI 相互独立。
</Callout>

## 故障排除

- **`401`** - `env_key` 中的变量尚未导出到运行 `codex` 的 shell 中。
- **shell/patch 工具未执行** — 检查模型及 Responses 路径的工具支持；文本回答不能证明工具已执行。
- **`400 previous_response_id`** — 移除 `previous_response_id` / `conversation`，在 `input` 中重发完整历史并使用 `store: false`。
- **模型未显示 / `404`** - 别名错误；`/v1/models` 显示了与您的密钥对应的有效列表。
- **旧版客户端** — 更新 Codex，并按[官方配置参考](https://developers.openai.com/codex/config-reference/)使用 `wire_api = "responses"`。
