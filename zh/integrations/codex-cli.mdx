[Codex CLI](https://developers.openai.com/codex/cli) 使用 OpenAI Responses 协议。将自定义提供程序指向 [`POST /v1/responses`](/zh/responses)；工具匹配和推理结果取决于所使用的模型和 Responses 路径。

<Steps>

<a id="instal-codex-cli"></a>

### 安装 Codex CLI

```bash
npm install -g @openai/codex
# atau: brew install codex
```

<a id="tambahkan-provider-hostlinku"></a>

<a id="添加提供商-hostlinku"></a>

### 添加 Hostlinku 提供商

编辑 `~/.codex/config.toml`（若不存在则创建）。提供商**必须**在此文件中定义——
出于安全考虑，项目内的 `.codex/config.toml` 文件不得覆盖 `model_providers`。

```toml
model = "gpt-5-3-codex"
model_provider = "hostlinku"
model_reasoning_effort = "medium"

[model_providers.hostlinku]
name = "Hostlinku"
base_url = "https://api.hostlinku.com/v1"
env_key = "HOSTLINKU_API_KEY"
wire_api = "responses"
```

<a id="set-api-key-dan-jalankan"></a>

### 设置 API 密钥并运行

```bash
export HOSTLINKU_API_KEY=sk-your-api-key   # simpan di ~/.zshrc / ~/.bashrc
codex
```

Codex 从名为 `env_key` 的变量中读取密钥；该密钥绝不会写入
`config.toml`。

<Callout type="tip" title="想通过GUI一键管理吗？">
  使用桌面应用程序 [CC Switch](/zh/integrations/cc-switch) 来添加和切换
  Codex 提供商/模型，而无需手动编辑 `config.toml`。
</Callout>

<a id="verifikasi"></a>

### 验证

发送一条简单的指令（例如 *“解释此仓库的结构”*）。该请求将显示在
控制台 → **请求日志** 中，模型为 `gpt-5-3-codex`。若要在
打开 Codex 之前确认端点：

```bash
curl https://api.hostlinku.com/v1/responses \
  -H "Authorization: Bearer $HOSTLINKU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "model": "gpt-5-3-codex", "input": "Halo" }'
```

</Steps>

## 通过配置文件调用多个模型

`cepat` 和 `kuat` 是您可以自由选择的示例名称，并非 Codex 或 Hostlinku 的默认配置文件。配置文件名称可以包含字母、数字、连字符和下划线。

Codex 会读取 `~/.codex/config.toml`。当你运行 `--profile <nama>` 时，Codex 也会读取 `~/.codex/<nama>.config.toml`。请为每个配置文件创建单独的文件，并在根级别进行设置；请勿使用 `[profiles.*]` 部分。请参阅 [Codex 官方配置文件指南](https://developers.openai.com/codex/config-advanced/#profiles)。

文件 `~/.codex/cepat.config.toml`：

```toml
model = "gpt-5-6-luna"
model_provider = "hostlinku"
model_reasoning_effort = "low"
```

文件 `~/.codex/kuat.config.toml`：

```toml
model = "gpt-6-astra"
model_provider = "hostlinku"
```

提供程序 `hostlinku` 仍定义在 `~/.codex/config.toml` 中。运行 Codex 时请选择配置文件：

```bash
codex --profile kuat
codex --profile cepat "tulis unit test untuk utils/date.ts"
```

<Callout type="warning" title="模型和工具的兼容性">
  请使用支持您所用 Codex 版本工具的原生 Responses 模型。Bridge Chat Completions 支持文本和函数调用；自定义工具 shell/patch 以及加密推理则需要原生支持。如果出现 `The requested tool type is not supported by this model` 提示，请更换模型或使用相应的 Chat/Anthropic 客户端。 请参阅 [Responses API](/zh/responses)。
</Callout>

<Callout type="note" title="无状态">
  在 `input` 中发送完整历史记录，并使用 `store: false`。Hostlinku 不接受非空的 `previous_response_id` 或 `conversation`，也不接受 `background: true`。加密的推理项仅在上游路径支持时才可使用；请参阅 [Responses API](/zh/responses)。
</Callout>

<Callout type="tip" title="只想替换默认的 OpenAI 端点吗？">
  无需新提供商的替代方案：在
  `config.toml` 中设置 `openai_base_url = "https://api.hostlinku.com/v1"` 以及 `OPENAI_API_KEY=sk-…`（Hostlinku 的 API 密钥）。仍建议使用自定义提供商
  ，因为其名称在用户界面中清晰可见，且密钥与原始 OpenAI 密钥相互独立。
</Callout>

<a id="troubleshooting"></a>

## 故障排除

- **`401`** - `codex` 运行所在的 shell 中，`env_key` 中的变量尚未导出。
- **shell/patch 工具未运行** — 请检查该工具在响应模型和路径中的支持情况；仅凭文本回答无法证明该工具已运行。
- **`400 previous_response_id`** — 删除 `previous_response_id`/`conversation`，在 `input` 中重新发送完整的历史记录，并使用 `store: false`。
- **模型未显示 / `404`** - 路径不正确；`/v1/models` 会显示与
  您的密钥对应的有效列表。
- **旧版客户端** — 请更新 Codex 并根据 [官方配置参考](https://developers.openai.com/codex/config-reference/) 使用 `wire_api = "responses"`。
