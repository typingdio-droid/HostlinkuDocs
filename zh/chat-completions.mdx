Hostlinku 的主要端点。请求和响应格式与
[OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat)，因此只需将 `base_url` 替换为 `https://api.hostlinku.com/v1`，
即可使用官方 OpenAI SDK。

```http
POST https://api.hostlinku.com/v1/chat/completions
Authorization: Bearer sk-your-api-key
Content-Type: application/json
```

成功响应包含 `x-request-id`；非流式传输的成功响应还包含 `x-model`（模型的公共 slug）。

选择适用于服务模式 API 密钥的可用模型。对 Vision、JSON 模式、推理和工具调用的支持均遵循该模型及其协议路径。请参阅 [兼容性限制](/zh/responses)。

<a id="parameter-body"></a>

<a id="body-参数"></a>

## 请求体参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `model` | `string` | 无 | **必填。** 模型别名，例如 `gpt-5-5`。参见 [模型](/zh/models)。 |
| `messages` | `array` | 无 | **必填。** 至少 1 条消息。每条消息格式为：`{ role, content, name? }`，其中 `role` 取值为 `system`、`developer`、`user`、`assistant` 或 `tool` 之一。 |
| `temperature` | `number` | 提供商默认值 | 范围为 `0`–`2`。数值越高，随机性越强。 |
| `top_p` | `number` | 提供商默认值 | 范围 `0`–`1`。`temperature` 的替代方案 _nucleus sampling_。 |
| `n` | `integer` | `1` | 答案选项数量，`1`–`8`。 |
| `stream` | `boolean` | `false` | SSE 流式响应时使用 `true`（见下文）。 |
| `stop` | `string` \| `string[]` | 无 | 一个或多个导致生成停止的文本序列。 |
| `max_tokens` | `integer` | 模型默认值 | 令牌输出限制（正值）。 |
| `max_completion_tokens` | `integer` | 无 | 现代替代方案 `max_tokens`（部分提供商使用）。 |
| `presence_penalty` | `number` | `0` | 范围 `-2`–`2`。 |
| `frequency_penalty` | `number` | `0` | 范围 `-2`–`2`。 |
| `user` | `string` | 无 | 用于追踪滥用的终端用户标识符。 |
| `tools` | `array` | 无 | 工具/函数调用的定义（OpenAI 格式）。 |
| `tool_choice` | `any` | 无 | 工具选择控件（`"auto"`、`"none"`、`{...}`）。 |
| `response_format` | `any` | 无 | 例如：`{ "type": "json_object" }` 用于 JSON 输出（取决于模型支持情况）。 |
| `seed` | `integer` | 无 | 种子确定性（尽最大努力，取决于提供商）。 |

<Callout type="note" title="参数验证">
  以上列表为主要参数。该架构还支持 `top_k`、`web_search_options`、`reasoning_effort`、`parallel_tool_calls`、`logprobs`、 `top_logprobs`、`logit_bias`、`stream_options`、`metadata`、`thinking`、`verbosity`、`service_tier`、`store`、`prompt_cache_key`、`safety_identifier` 和 `truncation`。未知的一级字段将被丢弃。 `messages[]` 中的附加字段（包括 `tool_calls`、`tool_call_id`、`function_call` 和 `reasoning_content`）将被保留。 对多模态参数和内容的支持仍取决于模型/协议。无效的请求主体将被拒绝，并返回 `422 VALIDATION_FAILED` 状态码及字段详细信息。
</Callout>

<a id="contoh-request-non-streaming-curl"></a>

## 示例：非流式请求（curl）

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-your-api-key" \
  -d '{
    "model": "gpt-5-5",
    "messages": [
      { "role": "system", "content": "Kamu adalah asisten yang ringkas." },
      { "role": "user", "content": "Jelaskan apa itu API gateway dalam dua kalimat." }
    ],
    "temperature": 0.7,
    "max_tokens": 256
  }'
```

回复（节选）：

```json
{
  "id": "cmpl_…",
  "object": "chat.completion",
  "created": 1770000000,
  "model": "gpt-5-5",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "API gateway adalah …" },
      "finish_reason": "stop"
    }
  ],
  "usage": { "prompt_tokens": 30, "completion_tokens": 55, "total_tokens": 85 },
  "hostlinku": {
    "cost": 0.00021,
    "latencyMs": 940
  }
}
```

`model` 包含 Hostlinku 的公共 slug。非流式成功响应中的 `hostlinku` 块包含费用、服务模式和延迟。该块并非每个 SSE 数据块中都保证包含的内容：

| 字段 | 含义 |
|---|---|
| `cost` | 费用以积分 🪙 计；1 积分 = 1 美元。 |
| `latencyMs` | 从网关接收请求到请求完成为止的总延迟，单位为毫秒。 |

<a id="流式传输-stream-true"></a>

## 流式传输（`stream: true`）

当 `stream: true` 时，网关将以 `Content-Type: text/event-stream`（SSE）响应，
以 OpenAI 兼容格式流式传输数据块 （每个数据块使用 Hostlinku 的公共 `id`
和相同的模型 slug），然后通过 `data: [DONE]` 关闭流：

```bash
curl https://api.hostlinku.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-your-api-key" \
  -d '{
    "model": "gpt-5-5",
    "messages": [{ "role": "user", "content": "Hitung 1 sampai 5." }],
    "stream": true
  }'
```

```text
data: {"id":"cmpl_…","model":"gpt-5-5","choices":[{"index":0,"delta":{"role":"assistant","content":""}}]}

data: {"id":"cmpl_…","model":"gpt-5-5","choices":[{"index":0,"delta":{"content":"1"}}]}

data: {"id":"cmpl_…","model":"gpt-5-5","choices":[{"index":0,"delta":{"content":", 2"}}]}

data: [DONE]
```

重要说明：

- 如果流处理失败，请将错误事件和连接中断视为失败。仅`[DONE]`标记并不能证明请求成功；请检查错误以及包含`x-request-id`的请求日志。
- 最终费用采用“使用量/上游费用”的表述；若为空或为零，网关可采用预留估计值。
- `x-request-id` 标头也会在流式响应中发送，以便与
  Console 中的日志建立关联。

<a id="contoh-python-sdk-resmi-openai"></a>

## 示例：Python（OpenAI 官方 SDK）

除 `base_url` 外，代码无需任何更改。OpenAI SDK 可直接使用：

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://api.hostlinku.com/v1",
    api_key="sk-your-api-key",
)

# Non-streaming
response = client.chat.completions.create(
    model="gpt-5-5",
    messages=[
        {"role": "system", "content": "Kamu adalah asisten yang ringkas."},
        {"role": "user", "content": "Halo dari SDK OpenAI!"},
    ],
)
print(response.choices[0].message.content)

# Streaming
stream = client.chat.completions.create(
    model="gpt-5-5",
    messages=[{"role": "user", "content": "Tulis satu paragraf pendek."}],
    stream=True,
)
for chunk in stream:
    delta = chunk.choices[0].delta.content if chunk.choices else None
    if delta:
        print(delta, end="", flush=True)
```

<Callout type="tip" title="将其他库中的 base_url 替换为">
  相同的规则也适用于 `openai-node`（`new OpenAI({ baseURL: 'https://api.hostlinku.com/v1' })`）、
  LangChain（`baseURL`/`openai_api_base`）以及其他支持
  。
</Callout>

<a id="error-yang-umum-di-endpoint-ini"></a>

## 该端点常见的错误

| 案例 | HTTP | `error.code` |
|---|---|---|
| Body 未通过验证（字段错误/类型错误/`messages` 为空） | 422 | `VALIDATION_FAILED` |
| API密钥无效或已过期 | 401 | `UNAUTHORIZED` |
| API密钥余额不足或限额已满 | 402 | `PAYMENT_REQUIRED` |
| 模型的 Slug 在目录中不存在 | 404 | `MODEL_NOT_FOUND` |
| `max_tokens` 超出了模型的输出限制 | 400 | `BAD_REQUEST` |
| 已弃用/暂时不可用的模型 | 503 | `MODEL_UNAVAILABLE` |
| 组织共享配额已超出 | 429 | `RATE_LIMITED` |
| 上游不可用/临时故障（可重试） | 503 | `UPSTREAM_ERROR` |

完整的错误封装格式请参见 [Error](/zh/errors)。
