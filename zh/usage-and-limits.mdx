用量受速率限制、密钥额度上限和组织余额约束。

## 组织共享配额

同一组织的所有 API 密钥及成员共享此配额。增加密钥或使用其他成员账户不会增加配额。

| Service Mode | 请求/分钟 | 输入 token/分钟 | 输出 token/分钟 |
|---|---|---|---|
| Performance | 600 | 6,500,000 | 200,000 |
| Low-Cost | 600 | 6,500,000 | 200,000 |
| Dedicated | 600 | 6,500,000 | 200,000 |

## 其他端点限制

Console、登录和 checkout 端点按 IP 限制，与模型使用配额分别计算。

| 范围 | 限额 | 计数单位 |
|---|---|---|
| 使用通用限流器的Console/公开端点 | **每60秒120次请求** | 每个IP |
| 使用认证限流器的端点 | **每15分钟30次尝试** | 每个IP |
| 令牌checkout的GET | **每60秒90次请求** | 每个IP |
| 令牌checkout的修改操作 | **每60秒15次请求** | 每个IP |

<Callout type="tip" title="等待后重试429">

读取重置标头或可用的 `Retry-After`。降低并发并使用带随机抖动的指数退避。不断立即重试无法解除限流。

</Callout>

## API 密钥额度上限

Console 表单提供 **Monthly Spending Limit**。密钥管理API还支持 `daily`、`weekly`、`monthly` 和总计 `lifetime`/不重置。日窗口从00:00 UTC开始，周窗口从周一00:00 UTC开始，月窗口从每月1日00:00 UTC开始。参阅 [身份验证](/zh/authentication)。

限额按密钥记录费用计算，不按Token数计算。达到上限后返回 `402 PAYMENT_REQUIRED`。增加余额不会改变密钥限额。

## 余额预留

网关从组织余额预留估算费用，转发请求后按上游usage结算并释放剩余预留。缺少usage时可能使用估算值。没有可计费用量的失败会释放预留。

新请求可用金额为 `available = balance − reserved`，余额和密钥限额都需要允许该请求。参阅 [计费与余额](/zh/billing)。

## Console 监控

| 菜单 | 数据 |
|---|---|
| **Overview / Analytics** | 按时间范围汇总请求、Token、缓存和费用 |
| **Logs** | 模型、状态、Token、费用、延迟、TTFT和详情 |
| **API Keys** | 状态、Service Mode、有效期、限额和密钥用量 |
| **Billing** | 组织余额、充值、交易和发票 |

非流式chat completion包含 `hostlinku.cost`。SSE分块不保证费用块；最终费用请查看Logs/Analytics/Billing。`x-request-id` 可关联请求与日志。

## 日志内容与保留期限

Body logging **默认关闭**。管理员开启后限制大小并遮蔽凭据字段，默认14天清理正文。用量/交易元数据仍保留。参阅 [隐私](/zh/legals/privacy-policy)。

## 429和402含义

| 代码 | 含义 | 操作 |
|---|---|---|
| `429 RATE_LIMITED` | 超出请求数限额 | 等待重置、退避、降低并发 |
| `402 PAYMENT_REQUIRED` | 可用余额不足或达到密钥额度上限 | 阅读消息后充值、等待重置或修改适当限额 |
