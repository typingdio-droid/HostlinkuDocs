## 响应格式

错误格式应遵循端点规范。`error.message` 消息用于说明问题；请使用 HTTP 状态码和错误代码/类型以实现自动处理。消息用语可能因服务而异。

**聊天补全和通用端点**使用 Hostlinku 代码：

```json
{
  "status": "error",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The request body is invalid.",
    "details": {
      "issues": [{ "path": "messages", "message": "Array must contain at least 1 element(s)" }]
    }
  }
}
```

**Anthropic Messages** 使用 `error.type`，`error.code` 中不包含 Hostlinku 代码：

```json
{"type":"error","error":{"type":"invalid_request_error","message":"The request body is invalid."}}
```

**OpenAI 响应**采用 OpenAI 格式和映射的代码：

```json
{"error":{"message":"The request body is invalid.","type":"invalid_request_error","param":null,"code":"invalid_request"}}
```

响应映射示例：`UNAUTHORIZED` → `invalid_api_key`，`MODEL_NOT_FOUND` → `model_not_found`，以及错误代码 429 → `rate_limit_exceeded`。 消息按类型进行分组，例如 `authentication_error`、`not_found_error` 和 `rate_limit_error`。

在聊天补全中，模式验证使用 **422**，但在消息/响应中使用 **400**。`error.details` 为可选字段；`error.details.issues` 指明无效字段。 在协议处理程序之前的错误（例如解析正文、请求限制或未知路径），可采用Hostlinku的通用格式。

## Hostlinku 代码

本表列出了 Hostlinku 在网关和通用端点中的代码。消息/响应采用上述映射规则；其他与账户或支付相关的特定代码可能会出现在相应的端点中。

| HTTP | 代码 | 含义与操作 |
|---|---|---|
| 400 | `BAD_REQUEST` | JSON/参数无法处理，包括模型输出限制。请修正请求。 |
| 400 | `MODEL_NOT_IN_SERVICE_MODE` | “Model”在“Service Mode”键下不可用。请从 `GET /v1/models` 中选择具有相同键的模型。 |
| 400 | `UPSTREAM_REJECTED` | 提供商拒绝了该请求。请阅读经过处理的拒绝原因并修正输入内容。 |
| 401 | `UNAUTHORIZED` | 身份验证不存在、错误、已被撤销或已过期。请检查密钥。 |
| 402 | `PAYMENT_REQUIRED` | 可用余额不足或密钥信用额度已达上限。请查看 [计费](/zh/billing)。 |
| 403 | `FORBIDDEN` | 访问被拒绝。请检查账户权限。 |
| 404 | `NOT_FOUND` | 路径或资源不可用。请检查 URL 和 ID。 |
| 404 | `MODEL_NOT_FOUND` | 模型的 Slug 不存在。请检查目录。 |
| 405 | `METHOD_NOT_ALLOWED` | HTTP 方法有误。请使用 `Allow` 标头中的方法。 |
| 413 | `BAD_REQUEST` | 有效载荷过大。请缩小正文大小。 |
| 415 | `BAD_REQUEST` | 不支持正文的编码/字符集。请检查正文格式。 |
| 422 | `VALIDATION_FAILED` | Body/query 验证失败。请修正 `error.details.issues` 中的字段。 |
| 429 | `RATE_LIMITED` | 按服务模式计算的组织配额或端点/IP限制已达到；上游也可能返回限制。请等待并降低并发量。 |
| 429 | `MODEL_AT_CAPACITY` | 提供商处的模型容量已满。请等待重试建议。 |
| 429 | `MODEL_COOLDOWN` | 部署模型正在从故障中恢复。请等待重试提示。 |
| 500 | `INTERNAL` | 内部错误。请保留请求信息，若问题反复出现请上报。 |
| 503 | `MODEL_UNAVAILABLE` | 该模型不可用或已弃用。请检查目录和替代模型；如果故障确实是暂时的，请重试。 |
| 503 | `PROVIDER_UNAVAILABLE` | 提供商路径不可用。请稍后重试。 |
| 503 | `UPSTREAM_ERROR` | 上游故障。请稍作等待后重试。 |
| 503 | `UPSTREAM_TIMEOUT` | 上游超时。请稍作等待后重试。 |
| 503 | `UPSTREAM_UNREACHABLE` | 无法连接上游。请稍后重试。 |

### Console 和 checkout

以下代码与账户/结账相关，而非 `/v1/*` 的错误推断合同：

| HTTP | 代码 | 含义与操作 |
|---|---|---|
| 403 | `API_KEY_NOT_ALLOWED` | API密钥用于Console账户的端点。请使用Console的登录会话。 |
| 409 | `CONFLICT` | 该操作与当前状态冲突。请在重试前重新加载状态。 |
| 424 | `CHECKOUT_FAILED` | 提供商无法生成账单。请阅读错误信息并检查交易记录，然后再尝试重试。 |
| 424 | `BANK_BUSY` | 您的 iPaymu 银行/渠道目前繁忙。请选择结账页面提供的其他银行。 |

## 重试和流式传输

如果存在，`Retry-After` 表示以秒为单位的等待时间，`retry-after-ms` 表示以毫秒为单位的等待时间。如果不存在，请使用带抖动和尝试次数限制的指数退避算法。 对于共享配额，在同一组织中添加密钥或成员账户不会增加配额；请参阅 [使用情况与限制](/zh/usage-and-limits)。

SSE 启动后，失败情况将作为错误事件发送到流中；初始 HTTP 状态保持不变。聊天补全示例：

```text
data: {"error":{"code":"MODEL_AT_CAPACITY","message":"The model is at capacity right now. Please retry shortly.","type":"upstream_error","retry_after_ms":4000}}
```

网关在处理流失败后不会添加 `[DONE]`。连接也可能在没有错误事件的情况下断开。 仅凭 `[DONE]` 标记或连接结束并不能证明操作成功；请检查错误事件和请求日志。事件 Messages/Responses 的格式在 [Messages](/zh/anthropic-messages) 和 [Responses](/zh/responses) 中有详细说明。

提交报告时，如有，请包含 `x-request-id`、事件发生时间、端点、模型、HTTP 状态码以及不含密钥的错误正文。请参阅 [支持](/zh/support)。
