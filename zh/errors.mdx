## 响应格式

错误格式取决于端点。`error.message` 说明问题；自动处理应使用HTTP状态和错误代码／类型。消息语言可能因服务而异。

**Chat Completions和通用端点**使用Hostlinku代码：

```json
{
  "status": "error",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The request body is invalid.",
    "details": {
      "issues": [{ "path": "messages", "message": "Array must contain at least 1 element(s)" }]
    }
  }
}
```

**Anthropic Messages**使用 `error.type`，不在 `error.code` 中包含Hostlinku代码：

```json
{"type":"error","error":{"type":"invalid_request_error","message":"The request body is invalid."}}
```

**OpenAI Responses**使用OpenAI格式和映射后的代码：

```json
{"error":{"message":"The request body is invalid.","type":"invalid_request_error","param":null,"code":"invalid_request"}}
```

Responses映射示例：`UNAUTHORIZED` → `invalid_api_key`、`MODEL_NOT_FOUND` → `model_not_found`、429错误 → `rate_limit_exceeded`。Messages将这些错误归为 `authentication_error`、`not_found_error`、`rate_limit_error` 等类型。

Schema验证失败在Chat Completions中返回 **422**，在Messages/Responses中返回 **400**。`error.details` 是可选字段；`error.details.issues` 指出无效字段。协议处理器之前的错误，例如正文解析、请求限流或未知路径，可能使用通用Hostlinku格式。

## Hostlinku代码

下表列出网关和通用端点的Hostlinku代码。Messages/Responses使用上述映射；账户或支付端点还可能返回其他专用代码。

| HTTP | 代码 | 含义与处理 |
|---|---|---|
| 400 | `BAD_REQUEST` | JSON／参数无法处理，包括模型输出上限。请修正请求。 |
| 400 | `MODEL_NOT_IN_SERVICE_MODE` | 模型不可用于密钥的Service Mode。请使用同一密钥从 `GET /v1/models` 选择模型。 |
| 400 | `UPSTREAM_REJECTED` | 提供商拒绝请求。请阅读经过清理的原因并修正输入。 |
| 401 | `UNAUTHORIZED` | 缺少身份验证，或密钥无效、已撤销、已过期。请检查密钥。 |
| 402 | `PAYMENT_REQUIRED` | 可用余额不足或达到密钥支出限额。请查看 [Billing](/zh/billing)。 |
| 403 | `FORBIDDEN` | 访问被拒绝。请检查账户权限。 |
| 404 | `NOT_FOUND` | 路径或资源不可用。请检查URL和ID。 |
| 404 | `MODEL_NOT_FOUND` | 模型slug不存在。请检查目录。 |
| 405 | `METHOD_NOT_ALLOWED` | HTTP方法错误。请使用 `Allow` 响应头中的方法。 |
| 413 | `BAD_REQUEST` | 正文过大。请减小正文。 |
| 415 | `BAD_REQUEST` | 正文编码／字符集不受支持。请检查格式。 |
| 422 | `VALIDATION_FAILED` | 正文／查询验证失败。请修正 `error.details.issues` 中的字段。 |
| 429 | `RATE_LIMITED` | 达到每个Service Mode的组织共享配额或端点／IP限制；上游也可能返回限流。请等待并降低并发。 |
| 429 | `MODEL_AT_CAPACITY` | 提供商的模型容量已满。请遵循重试建议。 |
| 429 | `MODEL_COOLDOWN` | 模型部署在失败后恢复中。请遵循重试建议。 |
| 500 | `INTERNAL` | 内部错误。请保存请求信息，反复出现时报告。 |
| 503 | `MODEL_UNAVAILABLE` | 模型不可用或已弃用。请检查目录及替代模型；暂时故障可重试。 |
| 503 | `PROVIDER_UNAVAILABLE` | 提供商路由不可用。请延迟重试并限制尝试次数。 |
| 503 | `UPSTREAM_ERROR` | 上游故障。请延迟重试并限制尝试次数。 |
| 503 | `UPSTREAM_TIMEOUT` | 上游超时。请延迟重试并限制尝试次数。 |
| 503 | `UPSTREAM_UNREACHABLE` | 无法连接上游。请延迟重试并限制尝试次数。 |

### Console和结账

以下代码用于账户／结账，与 `/v1/*` 推理错误契约分开：

| HTTP | 代码 | 含义与处理 |
|---|---|---|
| 403 | `API_KEY_NOT_ALLOWED` | 在Console账户端点使用了API密钥。请使用Console登录会话。 |
| 409 | `CONFLICT` | 操作与当前状态冲突。请重新获取状态后再试。 |
| 424 | `CHECKOUT_FAILED` | 支付提供商未能创建账单。请阅读消息并检查交易后再创建。 |
| 424 | `BANK_BUSY` | iPaymu银行／通道繁忙。请选择结账页面提供的其他银行。 |

## 重试与流式传输

`Retry-After` 表示等待秒数，`retry-after-ms` 表示毫秒。没有响应头时，请采用带抖动的指数退避，并限制尝试次数。同一组织内增加密钥或成员账户不会增加共享配额；请参阅[用量与限制](/zh/usage-and-limits)。

SSE开始后，故障以流内错误事件发送；初始HTTP状态不会改变。Chat Completions示例：

```text
data: {"error":{"code":"MODEL_AT_CAPACITY","message":"The model is at capacity right now. Please retry shortly.","type":"upstream_error","retry_after_ms":4000}}
```

网关处理流式故障后不会添加 `[DONE]`。连接也可能在没有错误事件的情况下断开。`[DONE]` 或连接结束本身不能证明成功；请检查错误事件及请求日志。各事件格式请参阅 [Messages](/zh/anthropic-messages) 和 [Responses](/zh/responses)。

报告时请附上可用的 `x-request-id`、时间、端点、模型、HTTP状态以及去除密钥的错误正文。请参阅[支持](/zh/support)。
