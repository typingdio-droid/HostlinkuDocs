以下代码使用Chat Completions格式。Messages和Responses有各自的错误格式；完整参考见[错误](/zh/errors)。

## 401 UNAUTHORIZED

在Console → **API Keys**检查密钥值和状态。网关端点接受`Authorization: Bearer sk-...`或`x-api-key`。不要用无效、停用或过期的密钥重试。

## 402 PAYMENT_REQUIRED

阅读错误消息：组织可用余额不足时充值；达到密钥额度时调整额度或等待重置。充值不会提高密钥额度。见[计费与余额](/zh/billing)。

## 404 MODEL_NOT_FOUND

该模型的slug在目录中不存在。请直接从`GET /v1/models`或[模型](/zh/models)页面获取确切的slug。请勿根据显示名称猜测slug。

## 400 MODEL_NOT_IN_SERVICE_MODE

虽然存在该模型，但不适用于当前使用的 Service Mode API key。例如：key“Low-Cost”调用了仅包含“Performance”路由的模型。请创建具有相应模式的 key，或选择其他模型。

## 422 VALIDATION_FAILED

修正`details.issues`指出的字段，例如空`messages`或错误类型。Chat Completions验证失败返回422，Messages和Responses返回400。见[请求示例](/zh/chat-completions)。

## 429 RATE_LIMITED

每个Service Mode的配额由组织共享。遵循`Retry-After`等待，采用退避并减少突发请求。被限流器拒绝的请求不会扣除余额。见[用量与限额](/zh/usage-and-limits)。

## 503 MODEL_UNAVAILABLE / UPSTREAM_ERROR

该模型已弃用/不可用，或者上游服务暂时出现故障。对于 `UPSTREAM_ERROR`，请稍后再试。对于 `MODEL_UNAVAILABLE`，请检查错误信息中是否包含 `replacement_slug`。

<Callout type="note" title="调试技巧">
请保存响应头中的 `x-request-id`。联系支持团队时，可使用该 ID 将请求与控制台日志进行匹配。
</Callout>
