## Format respons

Format error mengikuti endpoint. Pesan `error.message` menjelaskan masalah; gunakan HTTP status dan kode/tipe error untuk penanganan otomatis. Bahasa pesan dapat berbeda menurut layanan.

**Chat Completions dan endpoint umum** memakai kode Hostlinku:

```json
{
  "status": "error",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The request body is invalid.",
    "details": {
      "issues": [{ "path": "messages", "message": "Array must contain at least 1 element(s)" }]
    }
  }
}
```

**Anthropic Messages** memakai `error.type`, tanpa kode Hostlinku pada `error.code`:

```json
{"type":"error","error":{"type":"invalid_request_error","message":"The request body is invalid."}}
```

**OpenAI Responses** memakai format OpenAI dan kode yang dipetakan:

```json
{"error":{"message":"The request body is invalid.","type":"invalid_request_error","param":null,"code":"invalid_request"}}
```

Contoh pemetaan Responses: `UNAUTHORIZED` → `invalid_api_key`, `MODEL_NOT_FOUND` → `model_not_found`, dan error 429 → `rate_limit_exceeded`. Messages mengelompokkannya melalui tipe seperti `authentication_error`, `not_found_error`, dan `rate_limit_error`.

Validasi schema memakai **422** pada Chat Completions, tetapi **400** pada Messages/Responses. `error.details` bersifat opsional; `error.details.issues` menunjukkan field yang tidak valid. Error sebelum handler protokol, misalnya parsing body, pembatasan request, atau path yang tidak dikenal, dapat memakai format umum Hostlinku.

## Kode Hostlinku

Tabel ini merujuk kode Hostlinku pada gateway dan endpoint umum. Messages/Responses memakai pemetaan di atas; kode khusus akun atau pembayaran lainnya dapat muncul pada endpoint terkait.

| HTTP | Kode | Arti dan tindakan |
|---|---|---|
| 400 | `BAD_REQUEST` | JSON/parameter tidak dapat diproses, termasuk batas output model. Perbaiki request. |
| 400 | `MODEL_NOT_IN_SERVICE_MODE` | Model tidak tersedia pada Service Mode key. Pilih model dari `GET /v1/models` dengan key yang sama. |
| 400 | `UPSTREAM_REJECTED` | Penyedia menolak request. Baca alasan yang disanitasi dan perbaiki input. |
| 401 | `UNAUTHORIZED` | Autentikasi tidak ada, salah, dicabut, atau kedaluwarsa. Periksa key. |
| 402 | `PAYMENT_REQUIRED` | Saldo tersedia kurang atau limit kredit key tercapai. Periksa [Billing](/billing). |
| 403 | `FORBIDDEN` | Akses ditolak. Periksa izin akun. |
| 404 | `NOT_FOUND` | Path atau resource tidak tersedia. Periksa URL dan ID. |
| 404 | `MODEL_NOT_FOUND` | Slug model tidak ada. Periksa katalog. |
| 405 | `METHOD_NOT_ALLOWED` | Metode HTTP salah. Gunakan metode pada header `Allow`. |
| 413 | `BAD_REQUEST` | Payload terlalu besar. Kurangi ukuran body. |
| 415 | `BAD_REQUEST` | Encoding/charset body tidak didukung. Periksa format body. |
| 422 | `VALIDATION_FAILED` | Body/query gagal validasi. Perbaiki field pada `error.details.issues`. |
| 429 | `RATE_LIMITED` | Kuota organisasi per Service Mode atau batas endpoint/IP tercapai; upstream juga dapat mengembalikan pembatasan. Tunggu dan kurangi konkurensi. |
| 429 | `MODEL_AT_CAPACITY` | Kapasitas model penuh di penyedia. Tunggu saran retry. |
| 429 | `MODEL_COOLDOWN` | Deployment model sedang pulih setelah kegagalan. Tunggu saran retry. |
| 500 | `INTERNAL` | Kesalahan internal. Simpan informasi request dan laporkan jika berulang. |
| 503 | `MODEL_UNAVAILABLE` | Model tidak tersedia atau deprecated. Periksa katalog dan model pengganti; retry bila gangguan memang sementara. |
| 503 | `PROVIDER_UNAVAILABLE` | Jalur penyedia tidak tersedia. Coba lagi dengan jeda terbatas. |
| 503 | `UPSTREAM_ERROR` | Gangguan upstream. Coba lagi dengan jeda terbatas. |
| 503 | `UPSTREAM_TIMEOUT` | Upstream melewati batas waktu. Coba lagi dengan jeda terbatas. |
| 503 | `UPSTREAM_UNREACHABLE` | Upstream tidak dapat dihubungi. Coba lagi dengan jeda terbatas. |

### Console dan checkout

Kode berikut berkaitan dengan akun/checkout dan bukan kontrak error inferensi `/v1/*`:

| HTTP | Kode | Arti dan tindakan |
|---|---|---|
| 403 | `API_KEY_NOT_ALLOWED` | API key dipakai pada endpoint akun Console. Gunakan sesi login Console. |
| 409 | `CONFLICT` | Operasi bertentangan dengan state saat ini. Muat ulang state sebelum mencoba lagi. |
| 424 | `CHECKOUT_FAILED` | Penyedia gagal membuat tagihan. Baca pesan dan cek transaksi sebelum membuat ulang. |
| 424 | `BANK_BUSY` | Bank/kanal iPaymu sedang sibuk. Pilih bank lain yang ditawarkan checkout. |

## Retry dan streaming

Jika tersedia, `Retry-After` berisi detik tunggu dan `retry-after-ms` berisi milidetik. Jika tidak ada, pakai backoff eksponensial dengan jitter serta batas percobaan. Untuk kuota bersama, menambah key atau akun anggota pada organisasi yang sama tidak menambah kuota; lihat [Pemakaian & Limit](/usage-and-limits).

Setelah SSE dimulai, kegagalan dikirim sebagai event error dalam stream; HTTP status awal tidak berubah. Contoh Chat Completions:

```text
data: {"error":{"code":"MODEL_AT_CAPACITY","message":"The model is at capacity right now. Please retry shortly.","type":"upstream_error","retry_after_ms":4000}}
```

Gateway tidak menambahkan `[DONE]` setelah kegagalan stream yang ditanganinya. Koneksi juga dapat putus tanpa event error. Penanda `[DONE]` atau akhir koneksi saja tidak membuktikan sukses; periksa event error dan log request. Format event Messages/Responses dijelaskan pada [Messages](/anthropic-messages) dan [Responses](/responses).

Saat melapor, sertakan `x-request-id` bila tersedia, waktu kejadian, endpoint, model, HTTP status, dan body error tanpa secret. Lihat [Dukungan](/support).
